# research-engine：Pith 的事实调查引擎

v0.3 Fact Research（`docs/decisions/0020-v0.3-plan.md`）的纯逻辑部分。不联网、不碰数据库、不依赖 Tauri 和 macOS；真实的模型、搜索、下载接口在 `src-tauri/src/research/`，经 `ports` 里的 trait 接进来。

原则：模型只负责「读」和「写」（拆问题、从正文里摘事实、把核实过的事实写成结论），核对、可信度、计算都由代码做，并且能从头重做一遍来查（`audit`）。

| 模块 | 作用 |
| --- | --- |
| `dec` | 精确的十进制小数（不用浮点），除法保留 8 位、四舍五入 |
| `fold` | 文字折叠：去空白、全角换半角；折叠后的位置能对回原文 |
| `numbers` | 认数：千分位、小数、负数、万 / 亿、% / ‰ / 百分点、常见单位、区间；日期和编号不当成数 |
| `verify` | 事实核对：摘录在保存的正文里逐字找得到（只容忍空白和全半角）；数值在摘录里；单位紧跟着数，或在另一处写明单位的原文里（表格） |
| `trust` | 可信度等级表：按数据生产者的类型分高 / 中 / 低；默认表把中国政府官方统计列为低，设置可以覆盖 |
| `calc` | 差、比、变化率、平均、合计：模型只说算什么，代码算，写出算式 |
| `conclude` | 结论核对：`{F1}`、`{C1}` 占位符由代码填；模型自己敲的数逐个对，对不上的标出来 |
| `prompts` | 计划、摘证据、结论三段提示词，输出的 JSON Schema 和宽容的解析 |
| `ports` | 模型、搜索、下载、存档的接口 |
| `flow` | 一次调查：`plan` 停在等用户确认；`execute` 从 `run.stage` 接着做，每步存一次；取消、超预算、出错后可以接着做 |
| `diff` | 重查对比：按（指标、地区、人群、时间）对齐已核实的事实 |
| `report` / `render` | 报告的内容（来源、事实按可信度排，写明等级表）；Markdown 和单文件 HTML；`render::Doc` 也给 Word 导出用 |
| `audit` | 审计：对存下来的调查重新核对事实、可信度、计算、结论，列出对不上的地方 |
| `fixture` | 合成夹具（虚构的示例市）和模拟的模型、搜索、下载 |

## 一次调查的数据

`model::Run`：问题、计划（子问题）、搜索记录、来源（S1…）、事实（F1…）、计算（C1…）、结论（K1…）、步骤与费用。整份可以存成 JSON；来源的正文不在里面，由 `Fetch::text` 从快照读。

## 命令

```bash
cargo test -p research-engine
```

```bash
cargo run -p research-engine --example report
```

```bash
cargo run -p research-engine --example report html 2 > /tmp/report.html
```

第二、三条在合成夹具上跑一遍并打印报告（不联网）；`2` = 再重查一次并带上新旧对比。

## 测试

- 各模块自己的单元测试（数值解析、折叠、核对、计算、结论、提示词解析、对比、渲染）。
- `tests/flow.rs`：整条流程（计划 → 检索 → 下载 → 摘证据 → 核对 → 结论 → 报告 → 重查对比）、取消后接着做、超预算、单个来源失败、全部读不了。
- 改坏测试，两层都测：
  - 模型的输出被改坏（摘录改一个字、数字改一位、单位错、结论里多一个对不上的数）→ 流程拦下，不进结论或在结论旁标出；
  - 存下来的结果被改坏（同上，另加：没核实的标成已核实、只改显示的数、改计算结果、抬高可信度、换掉保存的正文）→ `audit` 查出来；
  - 低可信来源被排到前面 → `audit_order` 查出来。

夹具见 `fixtures/README.md`。
