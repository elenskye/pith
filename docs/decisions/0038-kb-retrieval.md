## 数据

- **migration 0011**（只加表）：`kb_members`（一份材料在哪几个库）、`passages`（材料的段落块）。表结构在 `docs/schema.md`。
- **一份材料能进几个库**：同一个来源（书、调查、卡片、对话里的一回）全库只有一份；再种进别的库只是多一个库。`kb_materials.kb_id` 改叫「家」：第一次种进的库，一定也在 `kb_members` 里；从家里拿掉而别的库还有它时，家换过去。所以删一个库只删只在这个库里的材料。没有把 `kb_id` 去掉：那要重建表，`migrations_only_add` 和投影式的升级测试就不成立了；留着当「家」反而方便（打开材料时去哪个库）。
- **段落块**：书一段一块（段落号、页码、所在的章，从 `concept_paragraphs` 原样抄一份，seq 一样，对齐靠它）；别的材料按空行切，太短的并、太长的在句末拆，单独一行的 `#` 小标题是标题块。调查报告、概念卡没有正文时用原来的东西（报告的 Markdown、卡片的句子）。重切时同一个位置的块留着原来的 id（编号 `[P123]` 不变）。书的文本删了，知识库里那份还在；重新解析了就重抄。
  - 抄一份而不是直接读 `concept_paragraphs`：1.3.0 起 PDF、Word、Markdown 都要进知识库，它们没有概念研究的表；1.5.0 概念研究改从知识库读以后，`concept_paragraphs` 在 2.0 拿掉。两本《国富论》一万多段，多几 MB。
- **升级**（启动时做一次，设置里记 `kb.v11`）：家补进 `kb_members`；同一来源在几个库里各一份的并成最早的那一份（生长阶段取高的、照料时间取近的）；**解析好的书迁成全文材料**，还没种进任何库的放进新建的「书架」；每份材料切段落块。整库恢复以后再做一遍（旧备份里没有 `kb.v11`）。以后新解析的书照旧在「种进来」里，不自动放进书架。

## 检索（`kb_search` 工具）

- **索引**是派生数据，在 `search.db`，删了能重建：按词 `search.kb_fts`（分词沿用文献库的中文二元组）、按意思 `search.kb_vecs`（本机向量模型，Qwen3-Embedding-0.6B）。书以前「问这本书」算过的向量（同一个模型、同样的文字）直接拿来。
- **补向量**在后台：种进来、改了正文、检索时发现缺就开始；设置 › 知识库与检索 能看到建到哪、能点「建索引」。不在每次启动时开（向量模型 1.6 GB，用到时才起）。
- **一次检索**：问题的向量 → 范围里最像的 40 块 + 按词的 24 块 → 书的译本那一边映射回原著、两边都找到的并成一条 → 本机重排模型打分（中文问题、原著是英文时比中译）→ 前几段。范围是这段对话勾的知识库，没勾是全部。退路和「问这本书」一样：本机模型用不了或者还没有向量 → 只按词；重排用不了 → 按向量排；都写一句说明给模型。
- 给模型看的：每段前面是编号 `[P123]`、书名、`[材料 12]`、段落号、页码、章名，书有对照时跟着对面那几段（也带编号）。

## 读原文（`kb_read` 工具）

- `passage` + `scope=context`：同一章里前后各几段；`scope=chapter`：整章，主对话只给约 9000 token，说还剩多少、整章交给子代理。
- `material`：目录（每章几段、多少字、从哪段起）；短的材料直接给全文；加 `chapter`（章号或章名）读那一章。
- `translation=true`：每段带上对照译文。
- **读整章交给子代理**：`delegate` 加 `chapter`（那一章任意一段的编号），程序把整章原文（带编号，最多约 6 万 token）直接交给强一档的子代理，不经过主对话的上下文；子代理的报告照样写编号，主对话转述时带着走。子代理也能用 `kb_search`、`kb_read`。

## 引用编号

- 模型在回答里写工具给的编号（`[P123]`，几段一起 `[P12, P34]`），程序按第一次出现的顺序换成 `[1]`、`[2]`；库里没有的编号原样留着（不改模型的话）。这是工具的用法，不是规定写法：不要求每句有出处（`0030`）。
- 页边注：种类（原文 / 旁注 / 注释 / 笔记 / 摘抄……）、书名和作者、段落号和页码、那一段原文、对照译文；「知识库里这一段」打开知识库面板、读到那一章、那一段亮着；「文献库」一步到书的条目。
- 正在写的时候编号也先换好（还不查库）。存下的页边注是当时的样子（材料后来改了，旧回答照样看得懂）。
- 交付卡「存进」的正文：编号换好，后面附「出处」一节（换了地方 [1] 还看得懂）。

## 知识库面板

- 书（和没有正文的报告、卡片）显示原文：一章一章读（下拉换章），从页边注过来的那一段亮着、慢慢退掉；书有对齐的译本时「对照」一键展开中译。
- 「在这些知识库」：一个个库的小标签，× 从那个库里拿掉，「＋ 也放进…」再放进一个库。拿掉最后一个库时说清楚「拿掉就没了」。

## 中英对齐用上语义相似度

- 原著和译本都在知识库里、两边正文段至少 95% 有向量时，用两段向量的余弦重新对齐（引擎的 `align_with`，权重是 11-15 在真书上定的），存回去并记下模型（`concept_alignments.similarity`）；同一个模型对过的不再算。补完向量时自动做。只用长度和锚点的对齐仍是默认（没向量、向量不全都不动）。
- 重新解析会把对齐换回只看长度的那份，补完变了的段落的向量后再用相似度对一遍。
- 概念研究打开时的审计用当时存下的对齐：对齐变了，个别原文句的中译核对可能变（变好或标出来），不改卡片。

### 在两本《国富论》上比一遍（App 自己的路，2026-11-26）

Penguin 英文版、杨敬年中译本：解析 → 迁进知识库成段落块 → 本机 Qwen3-Embedding-0.6B 补向量（8112 块，331 秒，不联网、不花钱）→ 两种做法各对一遍（`kb::tests::real_alignment`，默认忽略，命令在测试的注释里）：

| | 只用长度和锚点 | 加语义相似度（App 现在存的） |
| --- | --- | --- |
| 有正文的单元对上的 | 36 / 36（段数相同 20，算法对的 16，置信度低 1：附录） | 35 / 36（附录内容对不上，标成没对上） |
| 原著正文段有中译的 | 2096 / 2118 | 2083 / 2118 |
| 对法 | 1-1 2038、1-2 8、2-1 22、3-1 2 | 1-1 2043、1-2 6、2-1 17 |
| 算法对的 16 章、1555 段里对法一样的 | 1541（99.1%） | |

对着的 1-1 两段余弦 p10 0.76、p50 0.83。和 11-15 引擎上的结果（`concept-engine/README.md`「中英对齐」）一致：多数段落两种做法一样；差别在长度对得上、意思对不上的地方——附录不再硬对，被删掉的短段不再被并进旁边那一组。引擎上「改乱再找回」的测试（约每 8 段改一处：96.4% → 99.1%；每 3 段一处：89.2% → 98.1%）说明加相似度更准，所以 App 默认用它（有向量时）。加相似度对齐全书用时 4.3 秒。
