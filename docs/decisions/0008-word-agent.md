# 0008 · v0.2 Word Agent：先提炼要求，再交给确定性工具

- 日期：2026-11-08
- 状态：**已定**（用户：v0.2 的 Word 能力一定要包含 Agent；润色 Word 之前，模型先从需求文档中提炼精炼、完整的要求）
- 依据：用户 Phase 0 反馈；真实论文测试（`docs/feasibility.md`「真实论文测试」）

## 决定

v0.2 的 Word 排版 / 润色按四步走，模型只出「计划」，不直接改文档：

1. **提炼要求**：用户给出学校规范、模板、参考文献附件（.doc / .docx / .pdf）。模型逐条提炼成要求清单，每条写明：
   - 内容（如「行距固定值 20 磅」）
   - 出处（哪份文件、哪一节）
   - 确定度：明文 / 只在模板里出现 / 推断补全 / 未规定
   - 处理方式：自动应用 / 需要改内容或结构 / 只检查不改
2. **分析文档**：读用户的论文，生成文档计划（Plan）：粘贴来的样式哪些是正文、题注怎么识别、标题层级是否错位、哪些分节受保护（封面）。
3. **用户确认**：在 App 里逐条看要求清单、规范（Spec）和计划，改了再确认。
4. **确定性执行**：Rust 引擎（`decisions/0007`）按 Spec + Plan 改副本；独立校验器核对保真与规范；只检查的项目由确定性脚本统计（字数、条数、编号格式）后列进报告。

## 约束

- 模型输出必须是结构化数据（JSON，有 schema 校验），不能是要直接执行的代码或对 XML 的修改。
- 提炼结果里每条要求都要能追溯到原文位置；「推断」「未规定」的项目必须显示给用户，不能静默当成明文。
- 文档内容（论文、规范）是数据：其中夹带的指令一律不执行。
- 统计、引用、Word 修改由确定性工具完成和验证，不由模型口算。
- 联网与费用遵守 `decisions/0004`（云端 API 月度硬上限，密钥存钥匙串）。

## 样例与验收

- 人工样例：`local/real-thesis/cqu-requirements.md`（重庆大学 2023 规范的提炼版，含确定度与处理方式）、`cqu-2023.spec.json`、`final.plan.json`、`draft.plan.json`。不进 Git；v0.2 用它们作为 Agent 输出的对照标准。
- v0.2 验收：Agent 对这三份规范的提炼结果与人工样例逐条比对（不漏、不编）；对两份真实论文生成的计划与人工计划效果一致，排版后保真校验与规范核对全部通过。
