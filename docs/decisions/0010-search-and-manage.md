# 0010 · 搜索与管理：中文分词、编辑规则、回收站、去重

- 日期：2026-11-08
- 状态：已定（v0.1 Phase 3，Agent 按已定原则自行决定并实测，HANDOFF 汇报）
- 依据：需求 L5 / L6 / L9 / L10、`decisions/0003`（备份）、`0009`（导入）、`docs/schema.md`

## 1. 搜索（L5）

**索引**：`search.db` 以 `search` 名 ATTACH 到主连接，只存派生数据（可删了重建，不写 migration，不进备份）。一张 FTS5 表 `docs(title, creators, tags, abstract, notes, other)`，bm25 列权重 10 / 5 / 4 / 2 / 1 / 1。rowid = id × 4 + 种类（文献 / 附件 / 笔记），不另建映射表。

**文档** = 列表里的一行：文献（含回收站里的）、独立附件、独立笔记。子笔记正文、子附件的标题与文件名、标注原文与评论、子项上的标签都并进所属文献。回收站里的也索引，显示与否由列表按视图过滤。

**中文分词（需求说「实测后定」）**：在真实副本上实测两种方案（92 个文档；255 个查询词从库里自动取，只统计数字）：

| 类别 | 查询 | 子串真值 | 方案 1 漏 | 方案 2 漏 |
| --- | --- | --- | --- | --- |
| 中文 1 字 / 2 字 / 3–4 字 | 20 / 20 / 20 | 388 / 261 / 213 | 0 / 0 / 0 | 0 / 0 / 0 |
| 中文作者全名、中英混合 | 15 / 20 | 19 / 62 | 0 / 0 | 0 / 0 |
| 英文整词 / 前 5 个字母 | 20 / 20 | 310 / 379 | 4 / 24 | 0 / 0 |
| 英文词中间的子串 | 20 | 487 | 451 | 0 |
| 西文姓 / 标签 / 笔记里的词 | 20 / 20 / 20 | 41 / 58 / 245 | 3 / 2 / 3 | 0 / 0 / 0 |

- 方案 1：`unicode61 remove_diacritics 2`，建索引与查询时把中日韩连续文字改写成「重叠二元组 + 末字单字」（`政治效能感` → `政治 治效 效能 能感 感`），西文词前缀匹配。
- 方案 2：`trigram`，不足 3 个字的词改用 LIKE。
- 两种方案都没有「多找到」。方案 1 的「漏」全部是嵌在长词中间的子串（与「词首」真值相比 0 漏），例如 `form` 命中 reform，多半是误中。
- 方案 1 索引 416 KB、建 13 ms；方案 2 为 1048 KB、58 ms。查询都在 1 ms 内。5000 条合成文献：重建约 0.7 s，查询 1–12 ms。

**选方案 1**：中文与方案 2 一样准，不用为一两个字的词另走回退；西文按词头找，符合检索习惯；索引小一半多。

**查询**：多个词之间是「同时包含」；FTS 语法字符一律当普通文字；只有符号的词（emoji、`#`）按原文子串找。不支持繁简互通、词中间的子串、Müller ↔ Mueller。

**同步**：每个会改内容的命令在提交后按受影响的文档更新索引（失败只记日志，不让成功的修改报错）。启动时比对「文档集合 ↔ 列表行集合」，不一致就整体重建；设置页有「重建索引」。

## 2. 编辑（L10 与详情编辑）

- **字段为准**：所有改动写 `item_fields`，再由同一套规则（`fields.rs`，导入也用它）重算常用列。列永远由字段推出。
- 三个虚拟字段名落到这条文献实际用的字段上：`title`（案例是 caseName……）、`date`（写成 Zotero 两段式「排序值 原文」）、`container`（期刊文章是 publicationTitle、章节是 bookTitle……；图书等没有这一栏）。
- **换类型**：「期刊 / 书名」跟着换到新类型的字段；新类型没有这一栏时值留在原字段，不丢。
- **作者**：整组替换；有单栏姓名时只存单栏；空行不存。
- **界面**：常用字段就地编辑；其余字段收在「其他字段」里，也能改、能添加常用字段。回收站里的条目不能编辑。
- **批量**：多选后加 / 去标签、加入 / 移出集合、改字段（类型、语言、日期、期刊 / 书名、出版者、出版地）、移到回收站。一批里有一条失败就整批不改。
- **新建**：空白文献（手动），在集合里新建时直接放进该集合。**添加附件**：从本机选文件复制进文件库（原文件不动），可以是某条文献的子附件或独立附件。

## 3. 标签与集合（L6）

- 标签：加 / 去；没人用的标签自动删除；改名成已有名字 = 合并；删除 = 从所有记录上去掉。侧栏点标签筛选，多个标签是「同时带有」。
- 集合：新建（顶层 / 子集合）、改名、移动（不能移进自己或下级）、移到回收站（下级随它，里面的文献不动）。只有文献、独立附件、独立笔记能直接进集合，子附件 / 子笔记跟着文献。上级在回收站的集合算在回收站。
- 列表另有「未分类」（不在任何集合里的文献）、「文件缺失」、集合的「含子集合」开关。

## 4. 回收站

- 移进：只在直接操作的记录上写 `deleted_at`（S4 不变）。
- 恢复：上级也在回收站时一起恢复（子附件 → 文献；内嵌图片 → 笔记 → 文献；子集合 → 上级集合）。
- **永久删除**只接受回收站里直接删除的记录：先做 `before-delete` 备份（保留最近 3 份），子附件 / 子笔记 / 标注 / 下级集合随之删除，然后清理文件库里不再有人引用的文件（主文件看 `attachments.sha256`，快照资源看 `source_meta.extraFiles`）。删文件在数据库提交之后，删失败也不影响一致性。**Phase 6 起**：只删文件记录，文件本身留到没有任何备份用到时再删（`0013` 第 3 节），保证恢复备份时附件还在。
- 清空回收站 = 永久删除回收站里的全部。两者都要在界面上确认。

## 5. 去重（L9）

- **提示规则**：DOI（不分大小写）、ISBN（统一成 13 位）、规范化标题 + 年份相同的文献连成一组；标题少于 4 个字不比；回收站里的不算。
- **「不是重复」**：记在 `duplicate_dismissals`（migration 0003），这两条之间不再连线。
- **合并**：选一条保留；其余的子附件、子笔记、标签、集合、关联并过来；保留的那条缺的字段用别的补上（不覆盖已有值），没有作者时用另一条的；其余条目进回收站，并在保留的条目上记 `dc:replaces` 关联（可追溯，可从回收站恢复）。

## 不做（v0.1 Phase 3）

笔记编辑器、拖放（文献拖进集合、调整集合树）、标签颜色、撤销系统（v0.1.x 评估）、PDF 全文搜索（v0.1.x）。
