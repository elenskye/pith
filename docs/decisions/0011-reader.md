# 0011 · 阅读：文件协议、pdf.js、标注格式、阅读位置

- 日期：2026-11-08
- 状态：已定（v0.1 Phase 4，Agent 按已定原则自行决定并实测，HANDOFF 汇报）
- 依据：需求 L7 / L8、`decisions/0001`（pdf.js）、`docs/zotero-mapping.md` 第 4 节（标注格式）、`docs/schema.md`

## 1. 取文件：`rl-file://` 协议

- 界面用 `rl-file://localhost/<附件 id>` 取文件（Windows 上是 `http://rl-file.localhost/<id>`，`convertFileSrc` 处理）。Rust 按 id 查到文件库里的路径再读，界面拿不到也传不进本机路径，没有路径穿越的余地。
- 只给 **PDF 和常见图片**（png / jpg / gif / webp）。HTML 快照等不在 App 里显示（避免在界面里跑网页脚本），用「系统程序」打开。
- 查库时拿数据库锁，读文件时不拿（大文件读的时候别的请求不用等）。支持单段 Range、HEAD；跨域头只发给 App 自己的页面（打包后的 `tauri://localhost`，开发时还有 `http://localhost:1430`）。
- 阅读器一次取完整个文件交给 pdf.js（真实副本 28 个 PDF 共 33 MB，最大 6.8 MB），不走分段加载。

## 2. pdf.js

- `pdfjs-dist` 6.5.438（Apache-2.0）。用它自带的 `PDFViewer`（按需渲染、文字层、链接、查找），不用它的标注编辑器（那是写回 PDF 文件的；我们的标注存在库里，PDF 文件只读）。
- **体积**：阅读器连同 pdf.js 单独打包，第一次打开阅读器时才加载，启动包不变。新增：pdf.js 主体 + 阅读器约 0.64 MB、解析 worker 1.27 MB、样式 0.23 MB、运行时资源 2.9 MB（中日韩字体编码表 1.6 MB、替代字体 0.8 MB、图片解码 wasm 0.4 MB）。打包后前端共 5.3 MB。
- **不带**：PDF 内嵌脚本的解释器（quickjs，App 不运行 PDF 里的脚本）、无 wasm 时的后备脚本、XFA 表单。表单只显示不可填。
- PDF 里的网址链接交给系统浏览器（`app_open_url`，只认 http(s) / mailto），WebView 里不跳走。
- **文字层对齐**：pdf.js 量文字宽度的画布不带语言；文字层如果继承界面的 `lang="zh-CN"`，「sans-serif」会换成苹方，比页面上的字宽（合成 PDF 实测宽 8.6%），选区和高亮就对不齐。阅读器容器把 `lang` 置空后误差约 2%（与 pdf.js 自身相同）。PDF 自带语言时 pdf.js 用那个语言，两边仍一致。
- **真实副本兼容性**（`scripts/pdf-check.mjs`，只打印汇总）：28 个 PDF、532 页全部能打开；前 3 页都有文字层（没有纯扫描件）；5 个含中文；14 个有页码标签，其中 9 个标签不等于页序（期刊页码等），所以页码框和标注都按标签显示；没有缺字体编码表的警告；单个打开解析中位数 20 ms。

## 3. 标注（L8）

**格式与 Zotero 相同**，Zotero 导入的标注不用转换：

- 位置 `{"pageIndex":N,"rects":[[x1,y1,x2,y2],…]}`，PDF 用户空间坐标（pt，原点在页面左下），取 3 位小数；手绘为 `paths`。
- 排序键 `页|字符偏移|距页顶`（`00002|000123|00080`）。
- 颜色用 Zotero 的 8 种（黄红绿蓝紫品红橙灰），`#rrggbb` 小写。

**规则在 Rust**（`src-tauri/src/reader.rs`）：界面只把选区换成 PDF 坐标的原始矩形（一段文字一个）连同原文、页面框、选区在本页文字里的位置传过来；Rust 负责：

- 规整矩形、裁到页面里、去掉太小的；纵向重叠过半算同一行，同一行里间隔小于 0.6 个行高的并成一个（两栏之间不会并）；
- 整理摘录文字：合并断行（中文之间不加空格，西文行尾连字符断开的词接回去，下一行大写开头不接），空白并一个，去软连字符、零宽字符，拆开 ﬁ ﬂ 等连字；
- 算排序键；检查附件是 PDF、文件在、不在回收站。

**能做的**：高亮（8 色）、下划线、便签（点页面放一个 22 pt 的图标，与 Zotero 同大小）；改颜色、评论、摘录文字；删除（写 `deleted_at`，提示条上可撤销）；复制摘录（带页码）。来自 PDF 文件本身的标注（Zotero 的 external）只读。回收站里的附件（或所属文献在回收站）只能看。

**显示**：Zotero 导入的高亮、下划线、便签、区域（image）、手绘（ink）、文本框都画在页面上；位置坏了的不画，列表照常显示。标注原文与评论进搜索索引（并进所属文献），增删改后更新。

**跨页高亮**不支持（提示分两次选）。Zotero 7 的 `nextPageRects` 跨页格式导入后只画第一页。

## 4. 阅读位置

- 新表 `reader_states(attachment_id, state, updated_at)`（migration 0004），`state` 的键与 Zotero 的 `.zotero-reader-state` 相同：`pageIndex`、`scale`（`page-width` / `page-fit` / `auto` / 数字）、`top`、`left`（PDF 坐标）、`rotation`。只留认识的键、值不合理的丢掉。
- 翻页、缩放、滚动停下 0.8 秒后保存，关阅读器时立即保存；不改附件的修改时间。附件永久删除时随之删除。
- Zotero 里的阅读位置还没迁移（v0.1.x：格式相同，读 `.zotero-reader-state` 即可）。

## 5. 界面

- 阅读器占满窗口；文献库只是藏起来，返回时搜索词、滚动位置、选中项都还在。
- 打开方式：双击文献（打开它的第一个 PDF）或 PDF 附件；详情里的「阅读」；右键「阅读 PDF」。不是 PDF 的附件双击交给系统程序。
- 工具栏：返回、页码（可输标签）、缩放（自动 / 适合宽度 / 整页 / 50%–400%，⌘± ⌘0，触控板捏合）、便签、查找（⌘F）、系统程序打开、标注列表开关。
- 快捷键：←→ 翻页（页面比窗口窄时）、Delete 删除选中的标注、Esc 取消。

## 不做（v0.1 Phase 4）

PDF 全文进搜索索引（v0.1.x）、目录 / 缩略图侧栏、旋转、区域截图与手绘标注的新建、标注加标签、导出标注到笔记、阅读 EPUB / 网页快照、阅读位置迁移。

## 后果

- migration 0004 只加一张表和一个索引；旧库升级不改已有数据。
- 文字层对齐依赖 pdf.js 的测量与容器 `lang` 一致，也依赖 pdf.js 视图里是 `content-box`（0.1.1 修复：Tailwind 的 border-box 让画布比文字层小一圈，高亮越往页面右下错得越多；修复前在 App 里画的标注位置存偏了，用户重画）。以后若改界面的 `lang`、字体或全局盒模型，要重测高亮位置；开发版控制台会警告文字层与画布不一样大。
- 打包体积增加约 5 MB；阅读器不打开就不加载。
