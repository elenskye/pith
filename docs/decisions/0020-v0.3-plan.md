## 用户定的

1. **范围**：通用事实调查，什么问题都能问。验收问题：2022–2026 年北京、天津年轻人（应届生和非应届生）的就业情况，并与其他一线城市、热门二线城市对比。要弄清四件事：官方数字能不能直接比；官方与其他来源对不上时哪个更接近真实；特定人群的情况；给自己找工作、选城市做参考。
2. **指标**：青年（16–24 岁）失业率、平均工资（非私营 / 私营）、求人倍率、灵活就业与平台就业。另外要主动找更客观的数据和衡量维度。
3. **来源**：不限来源，按可信度排序。中国政府的官方数据（统计局、人社部门等）权重降到较低。
4. **呈现**：先给短答，展开才看全过程。导出 Markdown、Word（用 v0.2 的文档引擎）、单文件 HTML。用到的来源能在结论页一键加入文献库。
5. **检索**：Claude 网页搜索 + 本机下载，另接 Tavily。每接一个模型接口，都配好这个模型的专用搜索；没有专用搜索的用 Tavily。
6. **模型**：Opus 5.5 定计划、下结论；读网页、摘证据等执行工作交给便宜的模型，先用 DeepSeek（`deepseek-flash`）。
7. **预算**：和排版 Agent 共用一个月上限，提到 $30。不设单次上限。
8. **快照**：存原件、提取的正文、网址、抓取时间、哈希。
9. **证据层**：只做 v0.3 用得上的，存进主库。
10. **重查**：v0.3 就做。同一问题重查后，标出哪些数字、结论变了。
11. **视觉**：v0.3 仍然简约，视觉单独排一期。
12. **分工**：
    - 云端一口气做完它能做的部分（纯 Rust 逻辑、调查页面前端、合成夹具和自动测试），最后本地一次性验收。

    - 本地 Claude 可以自己抓取云端分支来验收。Agent 自己往 `CLAUDE.md` 写这条权限被安全检查拦下了，由用户自己加进规则 4（措辞见 `HANDOFF.md`）。
    - 云端做 v0.3 期间，本地做 v0.2 W5。

## 工程上直接定的

### 一次调查的流程

1. **计划**（Opus 5.5，可以用 Claude 网页搜索摸底）：
   - 把问题拆成可以核实的子问题。每个子问题写明指标、口径、人群、地区、时间、候选来源类型和搜索词。
   - 主动提出官方统计之外的衡量维度，例如招聘平台的岗位与薪资数据、独立调查与学术估计、社保参保、人口流动。
   - 用户在 App 里确认计划，可以删改子问题。
2. **检索**：每个子问题搜几次，网址去重。用户也可以手动加网址或文件（PDF、Excel、CSV、HTML）。
   - 搜索用执行模型绑定的引擎：DeepSeek 没有专用搜索，所以是 Tavily。
3. **下载**（本机）：Pith 在 Mac 上逐个下载。
   - 只取单页，不爬站，同一站点限速，User-Agent 不带个人信息。
   - 存原件，提取正文（HTML、PDF、XLSX / CSV），记网址、最终网址、抓取时间、SHA-256。
   - 下载失败的记原因。可以退回用 Claude 网页抓取（花 token，报告里注明）。
4. **摘证据**（执行模型，结构化 JSON）：从正文里摘「事实」，每条记：
   - 指标、数值原文、单位；
   - 地区、人群、时间、口径；
   - **数据生产者**：谁统计的，不是谁转述的；
   - 原文摘录和位置。
5. **核对**（代码，不靠模型）：
   - 摘录必须在保存的正文里逐字找得到，只容忍空白和全半角差异；数值必须出现在摘录里。
   - 数值解析（万、亿、%、‰、千分位）和单位换算由代码做。
   - 核不上的事实标「未核实」，不进结论。
6. **可信度**（代码，按设置）：
   - 按数据生产者分级，转述别人数据的按原始生产者算。
   - 默认等级表按用户的意见：中国政府官方统计、官方媒体转述的官方数字 → 低。
   - 等级表在设置里可以改，报告写明用的是哪张表。官方数字照样列出，只是降权并标明。
7. **结论**（Opus 5.5）：
   - 写 3–5 条短答，每条引用事实编号。
   - 需要的计算（差、比、同比、平均）由模型列出、代码执行。
   - 结论里每个数字都必须对得上一条已核实的事实或一个代码算出的值；对不上就打回重写一次，还不行就在结论旁标出。
   - 每条结论标不确定的类型：找不到 / 互相矛盾 / 已过时 / 口径没说清 / 只有低可信来源。
8. **报告**：
   - 短答在前；展开看子问题、搜索、来源（带可信度）、事实表（带核对状态）、计算过程和费用。
   - 导出 Markdown / HTML / Word。
9. **重查**：同一问题再跑一次，新旧按（指标、地区、人群、时间）对齐，标出变了的数字、新增和消失的来源、变了的结论。
10. 每一步都存进库里，可以取消；没有单次上限，但每次发出前仍列出要发的内容和预计费用（计划前一次，确认计划后一次），超过月上限照旧拒绝。

### 模型与搜索接口

- **接口抽象**：三类接口——模型、搜索、下载。
  - 模型：Anthropic Messages；OpenAI 兼容的 chat completions（DeepSeek 用这个）。
  - 搜索：Claude 网页搜索、Tavily。
  - 真实实现放 `src-tauri`；测试用模拟实现和录制的回复。
- **专用搜索**：设置里每个模型接口都有一栏「专用搜索」。Anthropic → Claude 网页搜索（`web_search_20260209`）；DeepSeek → 无，用 Tavily。以后加接口也照这个规则。
- **默认模型**：计划与结论用 `claude-opus-5-5`；执行用 `deepseek-flash`（`https://api.deepseek.com`，OpenAI 兼容）。模型名、接口地址、单价都在设置里可以改。
- **单价**（2026-11 的公开资料，F4 本地验收时对照官方价目页核对）：
  - Opus 5.5：每百万 token 输入 $4 / 输出 $20。
  - deepseek-flash：高峰 $0.30 / $1.20，闲时半价；按高峰价记账，宁可多记。
  - Claude 网页搜索：每千次 $10。
  - Tavily：基础搜索 1 点、高级 2 点，约 $0.008 / 点。免费额度也照价记进账本。
- **密钥**：Anthropic、DeepSeek、Tavily 各一把，钥匙串里各一个条目（`agent/secret.rs` 的 `ApiKey`，F0 已改好；Anthropic 的条目名不变，已存的密钥不用重填）。
- **账本**：沿用 `数据目录/agent/usage.jsonl`。每行加上接口和种类（模型调用 / 搜索），月上限对所有接口合计。默认上限改为 $30；用户在设置里存过的值不动。

### 代码与数据

- **新 crate `crates/research-engine`**：纯逻辑，不依赖 Tauri 和 macOS。包括流程状态、提示词、结构化输出解析、事实核对、数值解析与计算、可信度、结论核对、新旧对比、Markdown / HTML 渲染。
- **migration 0006（`research`）**：
  - 表：调查问题、每次调查、来源（快照路径与哈希、可信度、加入文献库后对应的条目）、事实、结论、结论与事实的对应、步骤与费用。
  - 只建表、加索引（`migrations_only_add`）。v5 的冻结夹具已经在（`src-tauri/fixtures/library-v5.json`），不用再冻。
- **快照文件**：数据目录 `research/sources/<sha256 前两位>/<sha256>.<扩展名>`，正文另存 `.txt`，同一文件只存一份。
- **加入文献库**：来源变成一条文献（网页 / 报告），原件作为附件，沿用附件的 SHA-256 去重。
- **Word 导出**：用 `docx-engine` 生成。
- **新依赖候选**：HTML 转正文、PDF 取文字、XLSX 读表（如 `calamine`）。云端评估许可证后登记 `THIRD_PARTY.md`。中文 PDF 取不出字的，标「取文字失败」，不静默。
- **版本号**：云端开工时改为 0.3.0（`package.json`、`src-tauri/Cargo.toml`、`tauri.conf.json`）。

- 短答里每个数字都能点回原文，并且核对通过；
