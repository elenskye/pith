## 一句话

**对话是做研究的入口，文献库是读原文、管资料的入口。** 事实调查、概念研究、排版、Word 润色、WonderLab 都做成技能（SKILL）。模型按问题在对话里自己挑、自己调用，用户也能点名用。设置页放这些技能的长期偏好和权限。

用户的原话：「把对话框和角色作为入口，而不是功能作为入口（文献库依然是独立的一个入口）」。

## 用户 11-21 认的（Atelier `HANDOFF.md` 第 3、4 节，抄在这里）

1. **默认一个研究助手，角色按需切换。**
   - 直接问，助手自己选技能。
   - 只有工作方式明显不同的才单独做成角色：「证据审阅」专查出处和反例，「写作编辑」守论文的引文和润色约定。
   - 角色是一份说明（身份、语气、行文），不收窄工具。
2. **自动调用要看得见，也要能纠正。**
   - 对话里用一行短状态说正在做什么（「正在核对 3 处引文」）。
   - 三步以上的任务显示待办；要用户定的事用问题卡问；成品用交付卡交出来。
   - 输入框旁边一个能力菜单：发现有哪些技能，`/<技能名>` 点名用。
3. **成果有自己的位置**：概念卡、证据表、WonderLab 作品、Word 修订预览都能从对话里打开大图，以后也能找回来。11-22 改了存的地方，见下面「存在哪」。
4. **技能写研究方法，App 的工具做精确操作。**
   - 技能判断怎么做（润色改多大、保留什么语气）。
   - 工具做确定的事：定位 Word 选区、生成修订预览、查文献库、核对引文、给页码和段落号。
   - 写回原文档（Word、文献库）之前，一定先把具体改动给用户看。
   - 原文 / 他人 / 解释 / 推演四类句子、引文逐字核对照旧由确定的代码把关。

**三个入口**

| 入口 | 管什么 |
| --- | --- |
| 对话 | 左边是按研究主题分组的对话；中间是对话，状态行、证据、能点回去的出处、交付卡都在里面；输入框旁边是角色和能力菜单，下面是用量圈 |
| 文献库 | 读原文、管资料：集合、标签、文献列表、详情、PDF / EPUB 阅读和标注（Zotero 八色不变）。选一段原文能「问 Pith」。详情里列出从这篇长出来的成果 |
| 设置 | 常规（通用、外观、备份与导出）；研究（角色、技能、知识库、文献库与引文）；模型与联网（模型与密钥、联网与用量） |

- 原来竖栏的「排版」「调查」「概念」不再是页面，变成技能。
- 可以借开源的 Deva（Electron 桌面 Agent，MIT）的做法：一个技能一个文件夹，`SKILL.md` 开头写名字和说明，模型平时只看见名字和说明，对上了才读全文。
- **不借** Deva 的「模型直接读写文件、执行命令、没有确认」。

## 用户 11-22 在 ASK 里定的

1. **Agent 循环 Pith 自己写**（Rust）。
   - 理由：以后会调很多家的 API，不能绑在一家的 SDK 上。
   - 用户点名要做好两件事：
     - **Prompt Cache 的前缀命中率。** 系统提示、工具定义、技能清单这些不变的放最前面，固定顺序。对话只往后追加，不改前面的内容。技能全文作为追加的消息读进来，不改系统提示。按每家的规矩打缓存断点（Anthropic 的 `cache_control`；OpenAI 自动前缀缓存），账本里记下命中的 token。
     - **递归式的轻量 Subagent。** 子任务用同一个循环起一个干净的上下文，只带它要的工具和资料，做完只交回摘要和成果。子任务还能再起子任务，有深度上限。子任务和主对话共用同一段前缀，好命中缓存。
2. **花钱只看月上限。**
   - 不再逐次确认，也不实时算每段对话花了多少。
   - 输入框下面一个小圆圈显示本月用量，点开看明细（像 Claude Code 桌面版）。
   - 账本照旧每次调用记一行。
3. **研究主题只给对话分组，知识库另建。**
   - 成果由模型自动存进对应的知识库或文献库，不和对话绑在一起。
   - 用户的说法：数据本质上在知识库，元数据本质上在文献库。
   - 所以对话可以删、可以换，研究留下来的东西在知识库里；文献的元数据、附件、标注在文献库。
   - 对话时勾选基于哪几个知识库。
4. **第一版（暂叫 v0.5）做这些**：
   - 对话 + 技能运行时 + 研究主题；
   - 旧功能改成技能：事实调查、概念研究、排版；
   - 摘抄与笔记进知识库：粘贴，或导入 Markdown 文件夹（Flomo、Obsidian 导出的）；
   - Word 润色技能：在选区上改写，写回前看修订预览。

   WonderLab 不在第一版。
