# 0002 · 与 Zotero 的关系、导入路径

- 日期：2026-11-07
- 状态：已定（问卷 Q1 / Q9 / Q15 / Q16）

## 决定

1. **目标是完全替代**：Research Lab 功能齐全后，用户会卸载 Zotero。因此 v0.1 的数据模型要能装下 Zotero 的全部核心信息（条目类型与字段、作者角色、集合树、标签、附件、笔记、相关条目），不能只做「够用的子集」。
2. **导入路径**：直接读 `zotero.sqlite` 的**只读副本**（实测 Zotero 9.0.3 / userdata schema 125），不经导出格式、不经本地 API。Phase 0-A 已验证可行，见 `docs/feasibility.md`。
3. **首轮只读**：导入不改 Zotero 任何文件；每条记录保留 `zotero_key` / `zotero_item_id`，用于重复导入时识别（增量导入冲突预览进 v0.1.x）。
4. **真实数据边界**：
   - 绝不读写 `~/Zotero/`。
   - 用户手动导出副本到 `~/ResearchLab-test/zotero-copy/`（项目外、只读、不进 Git）；步骤见 `docs/zotero-copy-guide.md`。
   - 仓库内的测试夹具只用合成数据（`tests/fixtures/`）。
5. **回收站**（2026-11-07 用户 ASK 确认）：Zotero 回收站里的条目和集合**原样导入 Research Lab 的回收站**，可恢复或清空，不丢数据。因此 v0.1 需要回收站状态与回收站视图。父条目在回收站时，子附件 / 子笔记随之在回收站（Zotero 不单独记录它们）。
6. **云端文件**：只在 Zotero 云端、本机没有的附件文件，迁移时标记为「文件缺失」并列入报告；条目照常导入。卸载 Zotero 前用户需先在 Zotero 里下载这些文件。
7. **不做**：Zotero 双向同步、Zotero 云同步、浏览器采集（后续版本再议）。

## Phase 0-A 验证结果（2026-11-07）

- 字段、作者、标签、集合、附件、笔记、标注、关联、回收站共 15 类，真实副本与合成夹具均 0 丢失。
- 映射细节见 `docs/zotero-mapping.md`。用户库没有 Zotero 标注、链接文件、group 库，这些只经夹具验证。
