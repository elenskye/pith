# 0032 · 1.0.3：控件换成 Pith 的样子，文献库两栏和标签树，换配色不卡

- 日期：2026-11-25
- 状态：现行
- 来源：用户 11-25「这一轮先做 UI 优化」的十条（Logo 对齐、去掉 ⌘K 提示、搜索框退场、换外观卡顿、下拉框和勾选框、文献库、知识库、文档、Git、本地验收）

## 定了什么

1. **换配色不卡**（实测见下）：拿掉整页的水面扭曲（SVG 滤镜）；颜色不再让十四个变量各自过渡，改成 View Transitions 从点的地方像墨一样洇开（`shared/theme.ts` 的 `saveLook`）。五圈波纹照旧，但要等洇开真的开始（`transition.ready`）才漾开：浏览器拍旧画面的约 0.2 秒屏幕是冻住的，早起的话最浓的一段被吃掉；洇开用和波纹同一种先快后慢的节奏（1.3 秒），一直跑在波纹前面，不然波纹被遮罩盖住（用户 11-25 看到「波纹完全去掉了」就是这两处）。没有 View Transitions、减弱动态效果时直接换。方案的 `palette-lake` 跟着改成 1.1.1（待批）。
2. **控件都是 Pith 的样子**（方案 `pith` 1.1.0 的 `Select`、`Check`、`Field`、`Strip`、`Tag`、`Dialog`、`TagTree`）：
   - 下拉框不用系统的 `<select>`（macOS 弹原生菜单，改不了样子），全换成 `shared/controls.tsx` 的 `Select`，选项照原来写 `<option>`；右键菜单、「新建」用同一个弹出列表 `Menu`。打开舒展、收起淡出（`usePresence`）。
   - 勾选框、单选框只靠样式：`<input class="pith-check">`、`pith-radio`。
   - 弹窗、提示条、就地编辑、标签输入的提示列表一起换了。
3. **文献库**：
   - 页头下两栏。第一栏左边是范围（全部、未分类，有东西时才出现的文件缺失、可能重复、待确认的补全、回收站），右边是类型和搜索；第二栏只放集合，一栏左右滑，有子集合的点开、子集合从一根小枝上接在后面（`library/Collections.tsx`）。选中某个集合时右边出「含子集合」。
   - 标签是一棵树（`library/TagTree.tsx`），画法和设置的枝桠一样；没有按钮，两指往右滑叫出来、往左滑收起（Esc 也收）——文献库里右滑叫的是标签树，别处还是对话历史。名字里有「/」的按前面那段分组。叫出来时页面往右让出一栏（排一次版，挪动用 transform）。
   - 右边的面板换成 Pith 的字段：小字的名、衬线的值、就地改；标签、集合是小胶囊；附件一行一个、后面几个小按钮；不再用 Lucide 的线性图标。
   - 导入从文献库挪到 设置 › 导入（设置变八页）；⌘K「从 Zotero、BibTeX 导入文献」去那里。原来的 `Sidebar.tsx`（藏在下拉里的集合树、标签）删了。
4. **知识库**借文献库的两栏：第一栏一排知识库 | 种类、搜索；第二栏是生长阶段；面板的字段和文献库的同一套。
5. 顶栏：Logo 的下沿和「Pith」的基线对齐（按基线排，蕨芽往下挪 6/48）；右上角不放 ⌘K 的提示。⌘K 关上时往上收、淡出。

## 为什么

- 卡顿是量出来的，不是猜的。`scripts/webkit-perf.swift` 开一个 WKWebView（和 Tauri 同一个 WebKit），跑 `src/dev/perfProbe.ts`，2.4 秒里数帧（1280 × 800，Retina）：

  | 情况 | 帧数（满 144） | 点下去到第一帧 | 超过 34 毫秒的帧 |
  | --- | --- | --- | --- |
  | 1.0.2 原样 | 66–72 | 105–113 毫秒 | 16–20 |
  | 只拿掉整页扭曲 | 144–145 | 13–16 毫秒 | 0 |
  | 只拿掉颜色过渡 | 69–74 | 90–114 毫秒 | 16–20 |
  | 拿掉扭曲、文献库 1500 行、颜色过渡 | 76–79 | 205–216 毫秒 | 5（150–280 毫秒） |
  | 同上、颜色直接换 | 127 | 204 毫秒 | 1 |

  无头 Chrome 里四种都满帧（Chrome 用 GPU 画 SVG 滤镜），所以要在 WebKit 里量。改成洇开、波纹放回来以后：

  | 情况 | 帧数 | 点下去到第一帧 | 超过 34 毫秒的帧 |
  | --- | --- | --- | --- |
  | 外观页点色板 | 144–145 | 22–32 毫秒 | 0 |
  | 文献库 ⌘K 换（假数据） | 143 | 45 毫秒 | 0 |
  | 文献库 ⌘K 换（1500 行） | 118 | 230 毫秒 | 4（最长 149 毫秒） |

  1500 行时剩下的是样式重算一次（表格没做虚拟滚动），和换配色本身无关。
- 整页的水面晃动没有便宜的替代：要逐像素扭曲页面，WebKit 只有 SVG 滤镜一条路，而它在 CPU 上算；只扭曲点附近一小块也得给整页套滤镜。所以先不要，波纹和洇开留着。
- 下拉框：原生菜单是系统的样子，和方案不搭；只换样式做不到，所以自己画，键盘、定位、退场都在一个组件里，换掉 16 处只改了调用。
- 集合不做下拉：一栏横排一眼能看到；Zotero 的集合是树，用「点开接在后面」保住层级，不另开一层。
- 标签树放左边、用手势叫：和对话历史同一种手感，页面上不多一个按钮（用户定的）。

## 没做的

- 技能里面那几页（调查、概念、排版、导入页的内容）和设置里原来那几块的按钮、小字还是旧的样子，只换了下拉框和勾选框。
- R1 画布还留着水面扭曲（原型，不是 App）。
- 窄的时候藏列不用 `@container`：WebKit 的容器查询管不到粘顶的表头，改成 ResizeObserver 量宽度写 `data-w`。
