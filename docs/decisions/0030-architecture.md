## 理念

**程序不限制模型，只给它更好的检索和引用工具。**用户 11-22 的原话：

> 程序不能限制模型，特别是“每句话有出处”这样的强限制。程序做的只能是，给模型提供更好的检索工具、引用工具，帮助模型更好更严谨地输出。

程序只做三件事：

- **给工具**：检索知识库、读原文、引用、计算、联网。页码、段落号、原文由工具给，模型不用背、不用猜。
- **守用户的文件**：改 Word、改文献库条目之前先给用户看改动，点头才写。
- **守边界**：月上限；不碰 `~/Zotero/`、`~/Pith/`；论文、网页、书里夹带的指令一律不执行。

不再做：给句子分类（原文、他人、解释、推演）；要求每句有出处、只许依据检索到的段落回答；核不上就删句子、打标签；用固定步骤表规定模型的先后。v0.3、v0.4 里这些规则在旧功能改成技能时拿掉（`0005` 的版本表里记着）。

## 四个入口、三层数据

| 入口 | 管什么 |
| --- | --- |
| **对话**（首页） | 一句问候、一个大输入框；对话历史没有按钮，⌘\ 或两指横滑叫出来 |
| **知识库** | 一个个知识库和里面的材料；加、整理也能在对话里说 |
| **文献库** | 条目、元数据、附件；PDF 阅读和标注（Zotero 八色）；Zotero 导入、联网补全 |
| **设置** | 七页：角色、技能、知识库与检索、模型与费用、Word 与引文、数据、外观 |

| 层 | 管什么 | 不管什么 |
| --- | --- | --- |
| 文献库 | 这是哪篇（条目、元数据、集合、标签）、文件在哪（附件、阅读、标注） | 不放摘抄和成果 |
| 知识库 | 能拿来检索、引用的东西：全文（带段落号、页码）、摘抄、笔记、网页快照、本机文件、扫描件，和成果（概念卡、调查报告、WonderLab 作品、存下的回答），十种 | 不管元数据，只记指向 |
| 对话 | 角色、对话、消息、引用、后台任务 | 不存原文，引用只记指向 |

- 数据在知识库，元数据在文献库（用户 11-22）：对话可以删、可以换，研究留下的在知识库。研究主题只给对话分组。
- 一份材料能进多个知识库（用户 11-22）。1.0.2 先按「一库一份、同一来源一库只种一次」存（`0031`），1.1.0 做检索时换成材料共享、段落块（`passages`）和统一索引，v0.4 解析好的书和卡片迁进来，不重新解析。
- 检索用本机的向量和重排模型（v0.4 修好的那套），回答用 API 模型。

## 对话 Agent

- **工具循环 Pith 自己写**（Rust，用户 11-22）：以后要接很多家 API，不绑一家 SDK。模型看问题自己定查什么、读什么、要不要再查、什么时候问用户、怎么写。
- **Prompt Cache**：系统提示、工具定义、技能清单放最前面、固定顺序；对话只往后追加；技能全文作为追加的消息读进来；按每家的规矩打断点，账本记命中的 token。
- **递归的轻量子任务**：同一个循环起一个干净的上下文，只带要的工具和资料，交回摘要和成果；有深度上限；和主对话共用前缀。
- **工具**：检索知识库、读原文、引用（编号 [n]，带出处，**不核对**）、查文献库、联网（快照进知识库）、计算（数字不口算）、加载技能、问题卡 / 交付卡 / 待办、后台任务、存进知识库、改 Word 和条目（先出修订预览）。
- **引用**：回答是普通文字，引了的地方带编号；点开编号在右边展开那一段原文，再一步回到文献库那一条。知识库里找不到，模型用自己的知识答。
- **看得见**：一行状态说刚才做了什么（每一步一个 Agent 图标），成果是交付卡，后台任务是任务卡。按钮只在要用户拍板的地方（问题卡的选项、修订预览的「应用」）。
- **花钱只看月上限**（用户 11-22）：不逐次确认，输入框下面一个用量圈，点开看明细；账本每次调用记一行。

## 技能

- 一个技能一个文件夹，一份 `SKILL.md`：开头名字和一句话，正文用文字写研究方法，可以带参考文档；不写步骤表。模型平时只看名字和说明，对上了才加载全文；用户也能 `/技能名` 点名。技能可以只给某几个角色用。
- 旧页变技能：事实调查 `/调查`、概念研究 `/概念`（还有问这本书、整章分析、追踪概念、反方、推演）、排版 `/排版`、Word 润色 `/润色`、WonderLab `/画`。留下的是工具（检索、下载与快照、解析、docx-engine、引文引擎），拿掉的是页面和固定流水线。
- 1.0.2 先把三个旧流程原样放进对话（`0031`），1.1.0 起改写成新格式。

## 角色（学 Deva）

- 一个对话绑一个角色（默认 Pith，不能删）；`@` 请别的角色答一回，对话还是原来的角色。
- 角色是一份说明（身份、语气、做事方式），加默认知识库、偏好模型、常用技能；**不收窄工具**。子任务不带角色设定。
- 对话里说「帮我建一个专看统计方法的角色」，Pith 拟一张角色名片让用户接受、改或拒绝。
- 初始四个（用户 11-22）：Pith（研究助手）、伴读、审稿人、编辑。只有做事方式明显不同的才单独做角色。
- 不取 Deva 的：没有确认就读写文件（Pith 写回之前一定给用户看）；手机 IM 机器人不做。多个角色组队原来不做，2026-11-26 问卷改成 2.0 之前做（`0035`）。
