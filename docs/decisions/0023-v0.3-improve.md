## 下载失败时改用 Claude 网页抓取

`0020`「流程」第 3 条写的「可以退回用 Claude 网页抓取」。F4 真实调查里 40 个来源有 4 个本机下载失败：网站返回 412、知乎 403、只支持旧 TLS 的网站、超过 25 MB 的 PDF。

- **什么时候用**：本机下载失败后，网址是 http(s)、不是本机或内网地址、没有被停止，并且设置里开着、填了 Anthropic 的密钥（没填就不用，下载失败照旧记原因）。用户手动加的本机文件不用。
- **怎么调**（`research/anthropic.rs` 的 `ClaudeFetch`，下载器外面包一层 `download::WithFallback`）：
  - 基础版 `web_fetch_20250910`（不走动态过滤，拿到的就是网页转成的文字或原 PDF），`max_uses: 1`、`max_content_tokens: 60000`，不开引用，不带结构化输出；
  - 网页抓取只抓对话里出现过的网址，所以网址写在用户消息里；
  - 默认模型 `claude-haiku-5-5`（便宜；只是调一次工具），设置里可以换；effort low。
- **拿到的东西**：网页是 `text/plain` 的文字，PDF 是 base64 的原件；照常存快照（原件 + `.txt` 正文）、取文字、算 SHA-256，后面的摘证据、核对、审计和本机下载的一样。
- **费用**：官方没有按次收费，抓到的正文按输入 token 计。发送前按最坏情况（正文按上限算两遍）查月度上限；记账 `purpose: research_fetch`；这次调用的费用随结果交给流程，记成「下载」那一步里的一行，报告的「过程与费用」里看得到。执行前的确认框多一行「下载失败的改用 Claude 网页抓取」（一般按一成来源失败估，最多按四分之一）。
- **报告里写明**：来源表里标「经 Claude 网页抓取」，「读之前要知道」里写有几个来源是这样拿到的。
- **存**：migration `0007_research_fetch.sql` 给 `research_sources` 加一列 `fetched_via`（只加列，`migrations_only_add` 照样通过；v6 的样本库 `library-v6.json` 已冻结）。
