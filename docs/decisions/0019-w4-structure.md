# 0019 · v0.2 W4 结构类排版：做法与验收

- 日期：2026-11-11
- 状态：已定（工程选择，可逆）。真实模型验收由用户 ASK 同意（上限 $3，实际 $1.63）。**还没有在 Word 里目视**（见「没测到的」），W5 验收补上。
- 依据：`0007`（文档引擎）、`0008`（模型只出计划）、`0018`（W3 排版 Agent）

W3 之前排版器只改格式（样式、页面设置、清手动格式），结构一概不动，校验器也据此要求「结构数量前后一致」。W4 做「要改内容或结构才能满足」的六类要求：每类都有编辑逻辑（`docx_engine::structure`）和独立核对（`docx_engine::verify_structure`）。

## 定下的

1. **结构类要求放进规范，文档自己的情况放进计划**（与 W3 的分工一致）：
   - 规范 `Spec.structure`：页眉内容（单面 / 双面奇数页 / 双面偶数页各自的左、中、右；章名写成 `{章名}`）与横线、页码（位置、前置部分与正文的数字形式）、正文从奇数页开始、三线表、脚注编号（形式、重新编号）、哪几级标题紧跟上一级时段前不空、多少页起双面。都由要求清单里的设置合成，记得来自哪条要求。
   - 计划 `Plan.layout`：前置部分、正文、正文之后各从哪一段开始（段落编号 + 开头文字，文字用来核对文档没变）、单面还是双面、哪些表格不排三线表。
2. **分区**：文档分成 封面 / 前置部分（摘要、目录）/ 正文（到致谢）/ 正文之后（声明等）。
   - 分界处没有分节符就加一个，写进分界前那个段落的属性里，**不新增段落**——所以正文文字、段落数前后完全一样。分界前紧挨着表格时不处理、报错让用户先加一个空段落。
   - 分界点前面只隔着空段落就是已有的分节符（真实论文里很常见）时，那些空段落算进后面的分区，不再多切一节（否则多一张白页）。
   - 切出来的前一半（封面）不带我们要管的页眉页码过去；后一半的分节类型重置（「奇数页起」跟着原来的位置走）。
3. **页眉**：前置部分和正文用规范写的内容；正文之后给空页眉（明确不要横线）；封面不动。
   - 章名用域 `STYLEREF 1`（按级别指内置的一级标题，不随 Word 的界面语言变；写样式名「Heading 1」「标题 1」换一种语言的 Word 就失效）。
   - 只有一处内容时用段落对齐；左、中、右并存时用制表位，位置按版心宽度算，并清掉页眉样式自带的制表位。
   - 新页眉页脚写成新部件 `word/header_pith<N>.xml`、`footer_pith<N>.xml`，原来的部件留着不删（没人引用，Word 下次存盘会清掉）。同样内容的只建一个。
   - 去掉这些分节的「首页不同」（否则每节第一页没有页眉页码）。
   - 单面 / 双面：双面时打开文档的「奇偶页不同」。规范两种都写了就各用各的；只写了一种就两种情况都用它。
   - **单面还是双面的默认值**：规范给了「多少页起双面」时，拿 Word 上次存盘记的页数（`docProps/app.xml`）比；排版后页数会变，所以只是默认值，计划页上可以改，并写明依据。
4. **页码**：页脚里一个 PAGE 域，位置按规范。前置部分、正文各自从 1 起、各用各的数字形式（每一节都要写数字形式，它不继承）；正文之后接着正文编。
5. **正文从奇数页开始**：正文第一节的分节类型设为 `oddPage`。
6. **三线表**：顶线、底线 1.5 磅，栏目线 0.75 磅（出版惯例；规范一般不写线宽，报告里注明），没有竖线和其他横线。
   - 表格和每个单元格的四条边都写明——单元格的设置优先于表格样式里的条件格式，不写明就可能被样式带回竖线。
   - 表头占几行：第一行有纵向合并的单元格时，合并到哪一行表头就到哪一行；否则一行。
   - **哪些表格排**：有边框的才排；没有边框的（用来排版的）、嵌套的、受保护分节里的、只有一行的、行外面包着内容控件或修订的不动，报告里逐个写原因。模型可以再指出「有边框但不是数据表」的（信息栏、签名栏），用户在计划页上逐个勾选。
   - 四线表（有合计行）不做，要求的说明里注明。
7. **脚注编号**：改文档设置里的编号形式（带圈数字 = `decimalEnclosedCircleChinese`）和重新编号方式；分节里单独写的会盖过文档设置，去掉。
8. **标题紧跟上一级标题时段前不空**：在那个标题段落上直接写段前 0。只认「紧挨着」——中间隔着空段落的不算（我们不删段落）。
9. **保真校验怎么放行结构改动**（`verify_structure::compare`）：允许的改动只有新的页眉页脚部件、它们在关系和内容类型里的登记、分界处多出来的分节符。**允许多少由校验器按规范和计划从排版前的文档自己推，不看排版器的报告**：新部件的名字得是那个形式、关系文件 = 原来的 + 每个新部件正好一条、内容类型 = 原来的 + 每个新部件一条、分节数正好多出该加的个数。别的照旧一个字、一个结构都不许变。
   - 受保护分节的外观核对改成按段落次序对（前面加了分节符以后分节号会变）。
   - 新增一项：排版后子元素顺序不合规定的元素不能比排版前多（顺序错了 Word 会报文件损坏；原文档里本来就有的不算）。
10. **生效核对**（`verify_structure::check`）逐项：分界处有分节符、每个分区每一节的页眉文字与章名域与横线、奇偶页设置、页码的数字形式与起始与页脚里的域、奇数页起、每个三线表的每条线、脚注编号、紧跟的标题的段前。规范要求了但计划里没给正文起点时，不猜：页眉页码不处理，核对里标一项「不符合」，如实告诉用户。
11. **Agent 这边**：
    - 要求清单多了五种「对象」（页眉内容、页码、版式、表格、脚注编号）和各自的属性，写法照旧是「对象 · 属性 = 值」，由 Rust 解析和核对。能做的结构类要求从「待做」变成「自动」；还做不了的（公式编号位置、四线表、表注、脚注分隔线、目录生成）仍是「待做」，列在报告里。
    - 文档计划多了两样：各部分的起点（模型只给段落编号，文字由 Rust 从文档里取；不在正文顶层的、空的、顺序不对的丢掉并说明）、不排三线表的表格。发给模型的论文摘要里，表格带上编号、行列数、有没有边框。
    - 计划页多了「分区」（三个起点各一个下拉，候选是一级标题；单面 / 双面）和「表格」（逐个勾选）两块；改了以后 Rust 重新核对。
    - **提炼太少时提示**：真实调用里出现过一次——两万字的规范模型只返回 1 条就结束了（JSON 合法、摘录也核对得上，重跑一次就正常）。现在条数与文档篇幅明显不相称时，在这套规范顶上提示「多半是模型没写完，建议重新提炼」。不自动重试（要花钱）。

## 验收

### 合成文档（自动测试）

`crates/docx-engine/tests/structure.rs` 10 项：一份「像论文」的合成文档上六类结构全做、单面与双面、已有分节符后隔着空段落、重复执行不重复加分节符、表格可以跳过、受保护的分节不动、没有正文起点时如实标出、过期或不可能的分界点被拒绝；**把排好的文档逐项改坏**（页眉文字、页码形式、去掉奇数页、表里加竖线、脚注编号、标题段前、正文文字、多一个部件、多一条关系、挪乱子元素顺序），校验器每一项都查得出。

### 真实论文，手写的规范和计划（不联网）

重庆大学规范（人工规范 + 结构类要求）配人工计划 + 分区：终稿保真通过、76 项全部符合（只新加了「原创性声明」前的一个分节符，另两处用的是已有的）；完整稿 1.0 保真通过、69 项全部符合。

## 没测到的

- **（W5 已补：在 Word 里看过，发现并修了多出空白页、表格文字挤断、参考文献悬挂缩进失效等问题，见 `0021`。）** 当时没有在 Word 里打开看过：两次申请操控（测试版 Pith、Word）都没有获准。页眉页码的实际显示、`STYLEREF 1` 在 Mac Word 里取到的章名、奇数页起时插入的空白页、三线表的线宽观感，都要目视确认。校验器保证的是文件结构：每条线、每个域、每个设置都在该在的地方，子元素顺序没有新的违规。W5 的第一件事就是在 Word 里看这几样。

## 没做的

- 公式编号的位置、四线表、表注的位置、脚注与正文之间的分隔线、目录的生成与各级格式、论文各部分的顺序：仍是「待做」。
- 封面本身（学校统一格式）不动；「首页不同」、分栏、横向页面的页眉没有专门处理（横向分节的制表位按它自己的版心宽度算）。
- 双面时没有打开「对称页边距」：规范没写，不擅自加。
