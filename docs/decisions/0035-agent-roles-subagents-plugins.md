# 0035 · Agent 的结构：角色 + 子代理 + 插件

- 日期：2026-11-26
- 状态：草案，跟 `0034` 一起等用户认。补充 `0030`「对话 Agent」「技能」「角色」三节；`0030` 里「多成员协作不做」由这里取代（问卷把「多个角色一起干活」放进了 2.0 之前）
- 来源：规划问卷第 1 页补充（角色学 Deva，子代理学本机 Peck 的 Harness，WonderLab、概念研究这些是插件，在插件库里管，分自带的和以后加的）；调研：Deva（`github.com/sqfcyily/deva`，MIT，2026-11-25 的版本）、Peck（`../personal-cli-studio/peck/src-tauri/src/harness/`、`gateway/`，只读参考）

## 一句话

一个 Rust 写的循环。**角色**定谁在跟你说话，**子代理**定谁去干活，**插件**定能干什么。三样在 1.1.0 就立住接口，按 `0034` 的版本一样样长全。

## 循环（1.1.0）

- **模型网关从 Peck 抽**（不整个复制 `loop.rs`，它是一个 40 个字段的大结构）：中立的消息和片段、每家一个编码器和流解析（Anthropic Messages、OpenAI、DeepSeek、Gemini、Vertex AI）、可重试的错误按 2/5/15/30/60 秒重发、随时能停、脚本化的模拟模型（测试和 `?mock`）、价格表。钥匙串、账本、月上限用 Pith 现有的（`agent/secret.rs`、`agent/usage.rs`）。Vertex AI 照 Peck 用 gcloud 的应用默认凭据（ADC）。
- **一轮**：调模型（流式）→ 跑工具（只读的并行跑）→ 结果接回去 → 下一轮。停：没有工具调用、轮数上限、月上限、模型拒答、打转（同一个调用同一个结果第 3 次提醒、第 5 次收尾）。
- **事件**：每一步一条带编号的事件，存下来（子代理的事件带它的 id）；前端照事件换状态行的 Agent 图标、出卡片，子代理的步骤收在派它的那一行下面。
- **Prompt Cache**：顺序固定为 工具 → 系统（App 的规矩、插件和技能的清单、角色）→ 对话；对话只往后追加；中途要插的状态用对话里的系统消息，不改开头；每家按它的规矩打断点，账本记命中的 token。
- **模型三档**（问卷：默认均衡，难的再换）：每家一档便宜、一档均衡、一档强；对话默认均衡（Anthropic 是 Sonnet 5.5，别家 1.1.0 第 1 期查各家现行文档定）。「难的再换」= 读整章、写长东西交给一个强一档的子代理，主对话留在一个模型上（缓存按模型分，来回换会白付）；你也能在一个对话里手动换。

## 角色（学 Deva；1.1.0 有分层，1.7.0 长全）

- **一个角色 = 说明 + 几样默认**：名字、一句话、头像、偏好模型、默认知识库、能用的插件（不写就是全部）；正文只写身份、语气、做事方式。正文里不放工具和安全规矩，所以换角色不会改变能力和边界。存在库里的 `roles` 表（`0010` 已有），设置 › 角色里改。
- **提示分层**，越往后越具体：App 的规矩（工具、边界、外部文本里的指令不执行、写回前给你看）→ 记忆的索引（1.8.0）→ 角色的正文。
- **插件可以只给某几个角色**：清单里没写就是都能用；删掉最后一个能用它的角色时，这个插件关掉，不会变成谁都能用。
- **对话里建角色**（1.7.0）：你说一句，模型拟一张角色名片（名字、一句话、正文），你改、接受或拒绝；模型自己不写角色。
- **组队**（1.7.0）：一个对话一个主角色，它统筹；`@审稿人` 请一个角色进来当成员，成员是单独的一条会话（自己的正文、模型、历史）。主角色派活给成员，成员默认用自己的名字直接回你，不再让主角色转述一遍；要汇总时才叫醒主角色。成员名单放在每条消息前面的一小块里，不放进系统提示（加人减人不打断缓存）。成员不能建角色、装插件。一个对话最多几个成员，1.7.0 定。
- **子代理不带角色**：查资料的不带语气，免得角色的立场歪了证据。

## 子代理（学 Peck；1.1.0 有底子，1.4.0 调查用，1.6.0 长全）

- **一个工具派活**：`派子代理(种类, 任务, 标题, 材料)`，立刻返回，子代理在后台跑。种类先定四个（照 Peck 的 explorer、searcher、auditor 改成研究用的）：
  - **查**：在知识库、文献库里找，只读；
  - **搜**：联网搜、取网页、存快照；
  - **读**：读整章、整本书，用强一档的模型，交回摘要和要点（带出处）；
  - **审**：拿一份草稿对着原文挑毛病，交回意见（只是意见，不删你的句子，`0030`）。
- **子代理拿到的**：同样的 App 规矩 + 它那一类的说明 + 任务 + 交给它的材料；看不到主对话。不能问你、不能存进知识库、不能写记忆；除「读」以外不能再派。
- **交回**：一批子代理全做完，结果一次接回主对话（每份有长度上限），主对话等它们做完再收尾。
- **上限**：每类同时跑 3 个（最多 8）；一次回答最多派 12 个；最深两层；每个子代理自己的轮数上限，到了给一轮「现在写报告」；花的钱算进主对话，共用月上限。
- **后台任务**（1.6.0）：一次调查、一整本书的研究放到后台，对话里一张任务卡；做完把结果交回那个对话（换了对话也不丢）。
- **存什么**：子代理的事件和交回的报告存下来，它自己的来回不存（照 Peck）。

## 插件（1.1.0 的工具先按插件分组，1.4.0 立格式和插件库）

- **格式照 Claude Code 的插件**（Peck 也是这样）：一个插件一个文件夹，`.claude-plugin/plugin.json` 写名字、说明、版本，加一节 `pith`：自带还是可选、要用哪几组工具、交付卡和结果页的种类、设置里的一块、给哪些角色；`skills/<名字>/SKILL.md` 用文字写研究方法（可以带参考文档），不写步骤表（`0030`）。
- **工具是 Rust 写的**，所以带代码的插件都随 App 发：自带的一直在，可选的在插件库里打开。以后加的插件只能带技能和参考文档（文字），不跑别人的代码。
- **模型怎么用**：平时只看每个技能的名字和一句话（顺序固定，在缓存的前缀里）；对上了或你打 `/名字`，才把全文作为一条消息读进来。打开、关掉插件会改工具清单，从下一个对话起生效。
- **插件库**：设置里「技能」那一页改成「插件」：一张张插件卡，写着带了哪些技能、哪些工具；分「自带」「可选」两栏；你自己写的技能放在一个「我的技能」插件里。
- **规划的插件**：基础（计算、问题卡、交付卡、存进）、知识库（检索、读原文、引用）、文献库、联网（1.1.0）；事实调查（1.4.0）；概念研究（1.5.0）；WonderLab（1.9.0）；学术研究（1.10.0）；排版和润色（等 engine-word）。旧的三个流程改成插件时拿掉固定流水线和四类句子（`0030`）。

## 从别处拿的，和不拿的

- **拿**：Deva 的角色写法、分层、按角色限插件、名片要你接受、成员直接回话、子代理不带角色、三层记忆（你、角色、知识库，1.8.0 再定细节）；Peck 的网关、重试、事件、子代理的种类和批次、上限、防打转、模拟模型、插件格式。
- **不拿**：Peck 面向写代码的那些（沙箱里跑命令、快照回滚、worktree、路径锁、命令行引擎）；Deva 不确认就读写文件（Pith 写回前一定给你看）、手机 IM 机器人。
