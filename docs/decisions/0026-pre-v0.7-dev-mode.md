# 0026 · v0.7 之前的开发方式：先建雏形，Agent 自己做真实验收

- 日期：2026-11-14
- 状态：**已被 `0029` 取代**（2026-11-24，版本号改从 1.0.0 起，本条的规则删掉）。原来：已定（用户定的），写进 `CLAUDE.md` 规则 8；`ROADMAP.md`「规矩」跟着改。
- 依据：用户 2026-11-14 在对话里的要求；`0005`（版本顺序，视觉放到 v0.7 之后）

## 用户定的

1. 用户在 v0.7 之后才开始真实验收，并打磨功能和视觉。
2. v0.7 完成之前，Agent 根据每轮问卷理清需求、架构和开发计划，按 Phase 开工；不要求人工验收，Agent 直接做真实验收，不阻塞开发。
3. v0.7 完成之前的目的是建立 Pith 的雏形，而不是保证能用。
4. 但 v0.7 之前也要做到尽可能完善，这样用户验收时不至于出现很多、很大的问题，甚至重构。

## 怎么落实

- **一版一轮问卷**：版本开头出问卷（Artifact），回答定了就写计划（决策 + ROADMAP 分期）并开工；中途只在「以后难改的取舍」上 ASK。
- **真实验收由 Agent 做**：用真实的书、文件、模型和接口，结果写进这一版的验收决策（如 `0025`）。花费：每版一个上限，上限内直接花，超了才问；默认 $5，第四轮问卷 D2 定（v0.4 整个真实验收花了 $0.69）。仍受 App 月上限约束，只用测试数据目录。
- **要用户亲自做的不挡开发**：攒进 `ROADMAP.md`「v0.7 之后：用户验收清单」，写清看什么、怎么看。v0.4 留下的（抽查卡片、Word 里插入原文、正式版填两把新密钥）已经挪进去。
- **防止以后重构**：数据结构、接口、模块边界按最终形态设计；测试、改坏测试、migration、备份、样本库冻结照旧；视觉集中在样式变量里，换视觉不改功能代码；已知问题如实记录。
- **退出标准改了**：v0.7 之前每期「做完」= 功能走通 + 自动测试 + Agent 的真实验收记录；「用户验收、日常可用」移到 v0.7 之后。

## 2026-11-15 补充（用户在对话和 ASK 里定的）

- 云端和本地并行，和 v0.3、v0.4 一样。
- 云端分支本地验收通过后，本地 Agent 直接合并进 `main`、提交验收中的改动并推送 `main`，不等用户。
- 同一天稍后用户再放开：以后 Git 都由本地 Agent 做，每轮做完自己提交并推送；提交信息按规则 7 的格式，不署名（`CLAUDE.md` 规则 4、7）。不 force push、不改写已推送的历史、不删分支、不改远端设置。
- 前几版留下的问题在 v0.7 之前全部做完，尽量交给云端。具体算哪些，第五轮问卷 E2 问。
- 第四轮问卷作废：WonderLab 的设计方向不对（程序把作品定死、过于忠实原文、时间轴和概念网络字多无聊）。重出第五轮；以后出问卷前先 ASK 几个决策点，问卷的选项配示意图。
