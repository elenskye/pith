## 用户定的

1. **材料**：英文原著、杨敬年中译本各一本 EPUB，由用户提供（检查结果见下一节）。Cannan 版（1904，公有领域）给云端做测试夹具。用户自己把两本 EPUB 发给云端会话，不进 Git。
2. **格式**：EPUB 为主。也要能读 PDF（新闻、短文这类篇幅不长的），PDF 用 **Mathpix API** 转文字，密钥由用户提供。长书默认 EPUB。
3. **定位**：段落号和页码都给；版本里没有页码的只给段落号。
4. **范围**：功能做成通用的（换章节、换书照样用）；验收只做分工三章（第一篇第 1–3 章）。
5. **做出什么**：概念卡、论证卡、关系图、反方与后世评论。**不定死**：这是 Agent 功能，原则上什么效果都能做；关键是把 Skill 和工作流做好，常用场景做成 Skill。
6. **三类内容**：原文说的 / AI 解释的 / 假设推演的。
   - AI 解释尽量挂原文；挂不上的照样显示，但要标明。
   - 假设推演单独一类，标明是推演、不是原著观点。
7. **反方与后世评论**：先查文献库，不够再用 v0.3 的检索找有出处的。
8. **入口四种**：整章分析、划选一段原文、问一个问题、跨章追踪一个概念。
9. **用途**：自己读懂和复习、写作时引用、做成知识作品（接 v0.5 WonderLab）。
10. **位置**：最左一列加第四个主页面「概念」，侧栏是书 → 章 → 卡片。原文直接显示在概念页里（带段落号），划选就能分析；不做完整的 EPUB 阅读器。
11. **书是文献库里的一条文献**（EPUB / PDF 是附件）；卡片引原文就是引这条文献。
12. **导出**：Markdown、Word（v0.2 的文档引擎）、单文件 HTML（关系图能点）。
13. **Word**：v0.4 就接上 v0.2 的引用引擎，能把卡片里的原文插成引文，带段落号或页码。
14. **模型**：GPT-6.1 Sol（OpenAI）。和排版、调查共用每月 $30；每次发送前确认，列出要发的内容和预计费用。
15. **分工同 v0.3**：云端做纯逻辑、页面、合成夹具和测试；本地验收，接真实的书和模型。
16. **做完的标准**：用户同意问卷里的建议（见文末）。

## 工程上直接定的

### Skill 与工作流

- **一个 Skill 是一个文件夹**：`SKILL.md`（开头是元数据：名字、中文标题、版本、说明、适用的入口、产出的内容种类、步骤；正文是给模型的做法，每步一节），可以带示例和测试（录制的回复与期望结果）。格式照 Brief 3.6 的设想，v0.7 Adaptive Agent 在这个基础上做自我改进。
- **存放**：内置的在仓库 `skills/`，随 App 打包；用户自己的放 `数据目录/skills/`。App 里列出全部 Skill，能在访达中打开。同名的用户 Skill 覆盖内置的，并标明。v0.4 不做 App 里的编辑器。界面上叫「技能」。
- **内置技能（v0.4）**：

  | 技能 | 入口 | 产出 |
  | --- | --- | --- |
  | 整章分析 | 一章 | 概念 → 论证 → 关系，三步，可以只选其中几步 |
  | 读一段 | 划选的段落 | 按内容出概念、论证、术语解释 |
  | 问这本书 | 一个问题 | 先在本地找相关段落，用户勾选后再回答 |
  | 追踪概念 | 一个概念 | 中英两种写法在全书里检索，按章列出用法与变化 |
  | 反方与后世评论 | 概念卡或论证卡 | 有出处的反对、修正和后世看法 |
  | 假设推演 | 论证卡或一段 | 改一个前提，推演会怎样（推演类） |
  | 自由 | 任意范围 + 用户写一句要求 | 笔记（如术语表、每章提要、复习题）；好用的再固化成技能 |

- **工作流**是技能里声明的几步，按顺序跑。步骤只有三种：模型（用正文里的哪一节、产出什么）、查文献库、网页检索（v0.3 的检索 + 本机下载 + 快照）。
  - 不让模型自己反复调工具：这样每步要发什么、最多花多少，发送前都算得出来（用户要求每次确认），也能用录制的回复测完整条工作流。
  - 以后要让模型自己决定调什么工具，再加有最多轮数、有最坏费用的那种。
- **产出统一成几种内容**：概念卡、论证卡、关系、评论卡（反方与后世评论）、推演卡、笔记。卡片样子由种类决定。每张卡由若干「句」组成，每句有类别和锚点（下一节）。任何技能的产出都走同一套核对，所以加新技能不用改代码。

### 文本层（书 → 章 → 段）

- **书与文献**：原著和译本各是一条文献（引用时著录不同），附件是 EPUB 或 PDF。附件「解析成文本」后得到一份文本；原著和译本的两份文本按段落对齐、互相关联。
- **EPUB 解析**：按书脊顺序读，用目录（EPUB 3 的 nav 或 EPUB 2 的 ncx）分出篇、章、节。段落是块级元素的文字。
  - 每段标角色：正文、标题、旁注、注释（脚注、尾注、译者按）、导读或导言、前后附（前言、索引等）。
  - 角色靠规则认，解析后给出结构预览（各章段数、各角色数量），用户确认后才存。
  - 小型大写之类的排版标记照原样取字，不改原文。
- **段落号**：只给正文段编号。
  - 两种写法：「篇.章.段」（Glasgow 式，`I.iii.5`）和通用的「章.段」（`3.5`）；目录有篇、章两层时默认用前一种，解析时可以换。
  - 旁注和注释挂在它前面的正文段上（如「I.i.3 旁注」「I.i 注 1」）。
- **页码**：从 EPUB 3 的 page-list、EPUB 2 的 `page-map.xml` 或正文里的分页锚点读，每段记下段内分页点的位置。一句引文的页码按它在段内的位置算，跨页的写「110–111」。
- **存进主库**：卡片要锚到段落，核对要用稳定的文字，所以解析结果存进主库，记下来源附件的 SHA-256 和解析器版本。只在用户要求时重新解析；重新解析后，按引文重新找锚点，找不到的列出来。
- **中英对齐**：同一章里正文段数相同，就按顺序对齐；段数不同的章不对齐，并标出来。v0.4 不做手动对齐。
- **PDF**（篇幅短的；默认超过 60 页提示改用 EPUB，设置里可以改）：
  - 走 Mathpix `v3/pdf`：上传 → 查状态 → 下载 `lines.json`（每页的行，带页号）和 `mmd`；由行拼段落，页码用 PDF 的页序。
  - 上传前确认（页数 × $0.005）。下载完调 `DELETE /v3/pdf/{id}`，删掉 Mathpix 上的副本。
  - 没填 Mathpix 密钥时用 v0.3 的本机取文字（`research/content.rs`），并提示中文可能乱码。
- **检索**：段落进 `search.db`（派生数据，FTS5 + 中文二元组，沿用 `search.rs`）。中文问题搜不到英文原著时，先搜对齐的中译段落、再映射回原著。

### 一次概念研究

1. 选入口和范围：
   - 一章；
   - 划选的段落；
   - 一个问题：本地搜出候选段落，用户勾选；
   - 一个概念：中英检索词，按章列出命中，用户勾选。
2. 选技能（入口给出默认的）。
3. 确认框：要发的段落（段数、字数、哪几种语言）、步骤、按最坏情况算的预计费用。
4. 执行：每步都存，可以取消，可以接着做。
5. 核对（代码做，见下一节）。
6. 结果：卡片和关系图。点锚点跳回原文段落，并高亮那句引文。
7. 后续：导出、在 Word 里引用、用同一技能对同一范围重跑（旧结果保留）。

### 内容的分类与核对

- **每句一个类别**：

  | 类别 | 是什么 | 锚点 | 核不上时 |
  | --- | --- | --- | --- |
  | 原文 | 原著正文 | 必须有；引文在所挂段落里逐字找得到 | 不进卡片，列进核对报告 |
  | 他人 | 有出处的别人的话：后世评论、反方，以及译本的旁注、注释、导读 | 必须有；锚到那份来源存下的正文 | 同上 |
  | 解释 | AI 解释 | 尽量有；挂的段落号必须存在，带引文的引文也要核对 | 没锚点照样显示，标「没挂上原文」 |
  | 推演 | 假设推演 | 不要求；可以引原文当前提（前提那句按原文类核对） | — |

- **逐字核对**沿用 v0.3 的折叠（只容忍空白和全半角），另外再容忍弯直引号、撇号的样式和拉丁字母大小写（EPUB 段首的小型大写）。这是概念研究自己的规则，不改 v0.3 的核对。
- **中英对照**：原文句以英文原著为准，模型同时给出对应的中译句；代码在对齐的中文段落里逐字核对中译句，核不上就只显示整段译文。
- **审计**：打开结果时，从存下的文本把所有锚点重新核对一遍（同 v0.3 的 `audit`），有问题在页面顶上标红。
- **改坏测试**：以下每一种都必须拦下——引文改一个字、挂错段落、引用不存在的段落号、标成原文却没有锚点、推演混进原文类、旁注或导读被标成原文、他人观点没有来源。

### 反方与后世评论

1. 先查文献库：用概念的中英检索词搜标题、摘要、笔记、标注；有 PDF 附件的取正文。列出候选，用户勾选。
2. 不够，或者用户选了「也上网找」：走 v0.3 的检索 + 本机下载 + 快照，下载规则和失败后备都照旧。
3. 模型从这些正文里摘观点，每条带引文；代码核对引文；网上的来源能一键加入文献库（沿用 v0.3）。
4. 没有出处的反方说法只能算「解释」类，并标明。

### 关系图

- 节点是卡片（概念、论证、评论、推演），边有类型：因果、包含、对立、举例、前提、修正。每条边带一句说明，说明也分类别、可以挂锚点。
- 布局在引擎里算（确定、可测，不引大依赖）。App 和 HTML 导出画同一份 SVG：点节点看卡片，点锚点看原文。

### Word 引文

- **搜索窗**（`src/picker`）：选中一本解析过的书时，多一栏「卡片里的原文」可选；定位可选「页」或「段」。
- **引文数据**：
  - 有页码的版本（英文）：locator 是页码，后面接段落号；
  - 没有页码的（中文）：locator 是段落号；
  - GB/T 7714 和 APA 7 下具体怎么显示，C3 各排一遍定下来。
- **把原文一起插进去**：宏在引文前面插入这句原文（加引号）。宏是 macOS 部分，C4 本地做；云端只做搜索窗和返回的数据。

### 模型与接口

- **默认 GPT-6.1 Sol**（`gpt-6.1-sol`），走 OpenAI Responses API（`v1/responses`）。官方模型页写着工具调用必须用 Responses API。
  - 结构化输出用 JSON Schema。
  - 推理深浅用 `reasoning.effort`（low / medium / high / xhigh / max），默认 medium，设置里可以改。
  - 带 `store: false`，不让 OpenAI 存对话。
  - 每步设 `max_output_tokens`（推理 token 也算在内），最坏费用按它算。
  - Opus 5.5 仍可在设置里选。
- **单价**（2026-11-13 官方模型页与价目页）：
  - GPT-6.1 Sol：每百万 token 输入 $2、缓存输入 $0.10、输出 $10。单次输入超过 272K 时整次按输入 2 倍、输出 1.5 倍计（分工三章远到不了）。
  - OpenAI 网页搜索：每千次 $10，搜到的内容按输入 token 计。
  - Mathpix `v3/pdf`：每页 $0.005。
- **专用搜索**：照 `0020` 第 5 条「每个模型接口都配它的专用搜索」，OpenAI 配 Responses 的 `web_search` 工具；没开就用 Tavily。
- **密钥**：钥匙串新加两个条目，`ApiKey::Openai` 和 `ApiKey::Mathpix`（Mathpix 是 `app_id` + `app_key` 一对，存在一个条目里），都放在「设置 › 密钥与费用」。
- **测试用的密钥文件**：OpenAI 和 DeepSeek 的密钥都以 `sk-` 开头，按形状分不开。改成每行写 `名字=密钥`，旧的写法照样认。
- **账本**：和排版、调查共用月上限。发送前按最坏情况查上限：输入估计 ×1.1 + 输出写满 + 搜索用满 + Mathpix 页数。
