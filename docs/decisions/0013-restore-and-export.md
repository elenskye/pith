# 0013 · 恢复、整库导出与升级测试

- 日期：2026-11-09
- 状态：已定（v0.1 Phase 6）。Agent 按 `0003` 与 HANDOFF 已列的方案决定并实测，HANDOFF 汇报。
- 依据：需求 L11、`decisions/0003`（数据目录与备份）；做法参考 Pomelo 的恢复（SQLite backup API，同一连接上整库替换）

## 1. 恢复（备份或整库导出）

1. **准备**（不占数据库锁）：把来源变成一个临时库并升到最新版本。
   - 备份：只认备份目录里名字合规的文件；只读打开，检查完整（`quick_check`）、是本 App 的库、版本不比 App 新。
   - 整库导出：见第 2 节。
2. **替换**（在主库的锁里）：停下联网补全 →「恢复前」备份 → 导出里的附件放进文件库（边复制边核对哈希）→ SQLite backup API 把临时库整库复制进主库（一步完成，失败时主库不变）→ 重建搜索索引。
3. **主库打不开时也能恢复**（损坏、版本比 App 新）：原文件连同 `-wal` / `-shm` 挪进备份目录、记为「恢复前」，在新建的库上恢复；恢复失败就挪回去。
4. 恢复之前开始的后台补全不会写进新库：库每换一次「代号」加一，补全线程读写前对代号。
5. 恢复后列表、详情全部重读，界面回到「全部文献」。

## 2. 整库导出（格式版本 1）

```
Pith 导出 YYYYMMDD-HHMMSS/
├── library.json   全部表、一行一条记录
├── attachments/   文件库里的文件，布局相同：<sha256 前 2 位>/<sha256>.<扩展名>
└── README.txt     内容说明与恢复方法
```

`library.json`：

```json
{
"format": "research-lab-library",
"formatVersion": 1,
"schemaVersion": 5,
"appVersion": "0.1.0",
"exportedAt": "2026-11-09T05:02:36.274Z",
"digests": {"items": {"rows": 88, "sha256": "…"}, …},
"tables": {
"items": [
{"id":1,"uid":"01J…","item_type":"journalArticle",…},
…
]
}
}
```

- **通用的表转储**：所有表、所有列（列名、含义同 `docs/schema.md` 对应版本），编号、时间、`source_meta` 等原样保留；以后 migration 新加的表和列自动包括，不用改导出代码。值只有整数、文字、空（有二进制列就拒绝导出）。
- 为什么不直接放 `library.db`：JSON 是普通文本，不靠本 App、不靠 SQLite 也能读，是离开本 App 的出口；一行一条记录，能用文本工具查看。
- `digests`：每张表的行数与摘要（行排序后逐行 SHA-256）。恢复时先核对，文件被改过、截断就拒绝。
- **导出后自检**：写完马上按导出重建一个临时库，逐表与库里比对，并重算全部附件文件的哈希；不通过就删掉这次导出、报错。
- **从导出恢复**：按导出时的版本建临时库 → 写入（一个事务，写完整体查外键）→ 逐表核对（导出 ↔ 重建的库）→ 升到最新版本 → 第 1 节的替换。导出里缺表、多表、多列、缺列都拒绝；比 App 新的格式版本 / 数据库版本拒绝。
- 附件文件缺失或损坏（导出时文件库里就没有，或导出后被改坏）：预览时提示个数，恢复照常进行，报告里写明几个打不开。

## 3. 附件文件什么时候删

- 备份只有数据库，附件文件在文件库里共用。所以**还有任何一份备份用到的文件不删**：永久删除时只删文件记录；每天第一次启动（旧备份清理之后）扫一遍，现在的库和所有备份都没有记录的文件才删。任何一份备份读不了就不删。
- 后果：永久删除后磁盘空间要等相关备份过期才回来；每月留一份的 daily 备份用到的文件会一直留着。v0.1 先保证「恢复哪份备份附件都在」。

## 4. 升级测试流程（`docs/testing.md`）

migration 只加表、加列、建索引（有测试检查），所以：

1. **每个旧版本**：把合成的完整库「投影」到第 N 版（只留那时有的表和列）→ 升到最新 → 旧数据逐表一致、App 的读取全部能用。
2. **冻结的样本库** `src-tauri/fixtures/library-vN.json`：每个版本用当时的代码生成一次（整库导出格式），以后每个版本都要能恢复并升级它。新增 migration 之前先冻结当前版本。
3. 一旦有 migration 要改已有数据，检查测试会失败，提醒为它单独写升级测试。

## 实测（2026-11-09，真实 Zotero 副本导入临时目录）

文献 88、附件 38、笔记 27、集合 22、附件文件 35 个（61.2 MB），22 张表 1,792 行：导出 + 自检 2.3 秒（library.json 393 KB），恢复到另一个空库 1.3 秒，22 张表逐行一致，文件全部在。

## 不做（v0.1）

- 合并式导入（把导出并进现有的库）：恢复只做整库替换。
- 压缩包、加密、定时导出、导出到云盘。
- 恢复单条文献（只能整库恢复，再手动挑）。
