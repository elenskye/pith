# 0012 · 联网补全元数据：来源、触发、合并规则

- 日期：2026-11-08
- 状态：已定（v0.1 Phase 5）。用户确认：导入后自动查；Crossref 请求带联系邮箱。其余由 Agent 按已定原则决定并实测，HANDOFF 汇报。
- 依据：需求 L3、`decisions/0004`（v0.1 唯一的联网功能，首次使用前提示范围，可关闭）、`0009`（导入）、`0010`（编辑规则）

## 1. 来源（只发 DOI / ISBN 本身）

| 标识 | 发给 | 怎么取 | 带邮箱 |
| --- | --- | --- | --- |
| DOI | `https://doi.org/<DOI>`，内容协商要 CSL JSON；doi.org 转给登记机构（Crossref、DataCite……） | 复用导入用的 CSL JSON 解析器（`import/formats`） | 是（User-Agent 里的 `mailto:`，Crossref 的「礼貌请求」） |
| ISBN | Open Library Books API | 书名（+副标题）、作者、出版者、出版地、日期、页数 | 否 |

- 一条文献先用 DOI 查，DOI 没有结果再用 ISBN 查。
- **不用 Google Books**：不带密钥时共享配额常被用完（实测返回 429），国内也常连不上。
- Crossref 的内容协商返回的类型名是它自己的（`journal-article`、`book-chapter`……），先换成 CSL 的再解析。
- 摘要是 JATS（`<jats:p>`）：去标签、保留段落、去掉开头的「Abstract」。标题里的 `<i>` 等去掉，副标题接在标题后。
- 不要的：`url`（doi.org 链接）、引用数、许可、`csl:` 原样字段。
- 节流：doi.org 两次请求至少隔 0.25 秒，Open Library 1 秒；429 / 502 / 503 / 504 按 `Retry-After` 等（1–20 秒）再试，最多再试 2 次；连续 3 次连不上网络就停下（不记失败，下次还会查）。
- HTTP：`ureq` 3.5.1 + macOS 系统 TLS（信任系统证书）；连接 8 秒、整体 25 秒超时；响应按字节读、不是 UTF-8 的坏字符替换掉。

## 2. 什么时候查

- **第一次用之前**弹出说明：发什么、发给谁、联系邮箱（可留空）、要不要自动查。用户同意才打开（`settings` 表：`metadata.enabled` / `metadata.auto` / `metadata.email`）。没打开时 Rust 拒绝联网，不只是界面不给按钮。设置页可随时关。
- **自动**（打开了「自动查」）：导入完成后查这次导入的文献；填了 / 改了 DOI、ISBN（或 extra 里的「DOI: …」）后查这一条。导入触发的，同一个标识查过（查到或确认没有）就不再查；改标识触发的，标识没变不查。
- **手动**：详情里「重新查」、多选后「联网补全 N 条」、设置页「补全全部文献」（已查过的跳过）。
- 都在后台队列里一次一条地查；联网时不占数据库锁，界面照常用；侧栏底部显示进度，可以停止。一轮开始前做一份 `before-metadata` 备份（保留最近 3 份）。
- **按 DOI / ISBN 添加**：新建菜单里粘贴一个或多个，联网查完逐条新建（来源记为 `lookup`）；库里已有的（DOI / ISBN 相同）不重复建；一次最多 50 个。

## 3. 合并规则（`metadata::plan`，有单元测试）

- **只自动填空着的字段**；作者整组为空时才填作者。DOI / ISBN 本身不动。
- 和现有不同的放进「待确认」，用户在详情里逐条「采用」或「忽略」；侧栏「待确认的补全」列出还有待确认的文献。只对这些字段提示不同：标题、日期、期刊 / 书名、卷、期、页码、出版者（学位论文的学校、报告的机构）、作者。摘要、语言、ISSN 等已有就不动，也不提示。
- 「一样」的判断：标题类按规范化文本（大小写、标点不计）；页码不计连字符写法；卷期不计前导零；**日期只比年份，且等于出版、印刷版、网络版任一个的年份都算一样**（期刊常常网络版先发、印刷版晚一年）；作者只比作者（不含编者）的姓。
- **按类型只补 Zotero 里有的字段**：例如期刊文章没有「出版者」，Crossref 给了也不补。文献类型与查到的不同时，只补标题、日期、摘要、语言和「期刊 / 书名」（落到这条文献自己用的字段上）。类型是笼统的「文档」时，建议改成查到的类型（待确认）。
- **撤销**：自动填的可以撤销；之后被改过的保留不动（标记「改过，保留」）。
- 每次查询记一行 `metadata_lookups`（migration 0005）：标识、触发方式、结果、来源、查到的记录、每处改动及其状态（applied / pending / accepted / ignored / undone / kept）。

## 4. 实测（真实副本，只统计数字）

`real_copy_lookup`：导入副本到临时目录，像导入后自动补全那样联网查一遍（带用户给的联系邮箱）。

| | 改规则前 | 改规则后 |
| --- | --- | --- |
| 有 DOI 或 ISBN 的文献 | 74（共 84） | 74 |
| 查到 / 没找到 / 失败 | 70 / 3 / 1 | 70 / 4 / 0 |
| 自动补上的 | 64 条、68 个字段（其中「出版者」61） | 4 条、6 个字段 |
| 待确认 | 23 条（日期 18） | 6 条（作者 4、出版者 2、标题 1、日期 1） |
| 用时 | 47 秒 | 32 秒 |

- 来源：Crossref 65、Open Library 5。没找到的 4 条里 3 条是中国 DOI 登记机构（chndoi.org）的 DOI，它不提供机器可读的元数据；1 条的登记机构返回的不是 JSON。
- 改规则前的问题：期刊文章被补了 Zotero 没有的「出版者」（61 处）；日期因网络版 / 印刷版差一年被标成不同（18 条）；一条响应不是 UTF-8 导致失败。三处都已改，见上文。
- 结论：Zotero 迁移来的数据本身已经比较完整，自动补全主要补零星的卷期页和机构名，不制造噪音；「待确认」的数量小到可以逐条看。

## 不做（v0.1）

中文书 ISBN 的其他来源（豆瓣等无公开接口）、中国 DOI（chndoi）的网页抓取、PubMed / arXiv ID、按标题模糊查找、附件 PDF 的元数据识别、定期重查。
