# 0006 · Word 动态引用：数据格式与接入路线

- 日期：2026-11-07 定数据格式；2026-11-08 用户确认接入路线
- 状态：**已定**
- 依据：Phase 0-B（`docs/feasibility.md` 0-B 一节）

## 决定

1. **文档内数据格式**（Word 内外通用）
   - 每处引文：行内内容控件，tag `rl:cite:<引文ID>`，内容锁定，防止手改成纯文本
   - 参考文献表：块级内容控件，tag `rl:bibliography`
   - 数据：Custom XML Part，命名空间 `urn:research-lab:citations:v1`，内含 JSON（样式、每处引文的文献 ID 与页码、文献快照），带数据版本号；版本比程序新时只读不改
   - 被删引文的数据不立即清理（Word 撤销后能恢复）；复制粘贴产生的重复 ID 刷新时换新
2. **引用引擎**：citeproc-js + 官方 CSL 样式 / 语言文件，按提交固定版本。刷新逻辑是一个纯函数（`planRefresh`），所有接入方式共用。
3. **接入路线**（用户 2026-11-08 确认）
   - **底座：Word 外直接改文件**。引用计算、排版、校验都在 Research Lab 里，任何时候都能对文件做确定性刷新与核对。
   - **主要入口：Zotero 式宏 + Word 顶栏**。Word 顶栏出现「Research Lab」选项卡，点开就是全部工具（插入引文、刷新、切换样式、排版……）。做法：全局模板（.dotm，含 RibbonX 与 VBA）放进 Word 启动文件夹，宏经 AppleScriptTask 调本机 Research Lab 服务。
   - **Office.js 加载项：代码保留，暂不启用**。等微软修复 Mac Word 的侧载问题（office-js #6973）后再评估是否替换宏。
4. **Word 里的按钮和提示一律用英文**（选项卡、按钮、宏对话框、状态栏）。Mac 版宏的对话框显示不了中文，统一用英文就不用绕。Research Lab App 本身、报告、文档仍然是中文。
5. **Zotero 已有的引文域**：只读识别、不改。v0.2 再做「Zotero 引文 → Research Lab 引文」转换（域代码里有 Zotero 条目 key，导入时保留了 `source_key`，可映射）。
6. **v0.1 数据模型已预留**：每条文献有稳定 `uid`（作为 CSL `id`），能导出 CSL-JSON。

## 实测依据

| 路线 | 本机实测 |
| --- | --- |
| Word 外改文件 | ✅ 生成 / 刷新 / 切换样式 / 校验全部通过 |
| Zotero 式宏 | ✅ 真实 Word 中插入、切换、保存、重开、删除、刷新全流程通过 |
| Office.js | ⛔ Word 16.114 忽略侧载清单（微软官方示例同样不识别）；机构账号下全部加载项被禁 |

## 后果

- v0.2 需要一个本机服务（Research Lab 主程序内）供 Word 宏调用，不再让宏直接起 Node（避免「文稿」文件夹权限弹窗）。
- v0.2 要做全局模板的安装与卸载（Word 启动文件夹在受保护的组容器里，需要安装步骤或引导用户手动放置）。
- v0.2 要解决：中文作者在 APA 里的写法、GB/T 顺序编码的页码（「[2]17」）、脚注类样式、跨文档复制引文。用户学校要求 GB/T 7714-2015 顺序编码制（重庆大学规范）。
- citeproc-js 是 CPAL-1.0 / AGPL-3.0 双许可：个人使用不分发没有问题；若将来分发需重新评估（候选 hayagriva，MIT / Apache-2.0）。
