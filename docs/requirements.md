# 需求（已定）

> 只写已经拍板的；细节和理由在 `docs/decisions/`，原始设想在 `docs/brief-digest.md`。来源：各轮问卷（2026-11-22 已删，答案在 Git 历史 `b128d24` 之前）、ASK 确认、各期验收反馈。
> 做完的版本只留仍然约束后续开发的要点。

## 总体

- 用户：一个人，研究生 / 研究者；文献以英文为主。
- 用途：写毕业论文、日常事实调查、读书学习；把 Zotero 迁移过来后卸载 Zotero。
- 使用方式：项目驱动，忙时密集用、平时不开 → 启动要快，不常驻服务。
- 驱动项目：复现毕业论文（v0.2）→ 北京、天津青年就业（v0.3）→《国富论》分工三章（v0.4–1.1.0）→ 政治效能感（1.2.0）。到对应阶段在 HANDOFF「等你」里提醒用户提供资料。
- 形态与栈 `decisions/0001`；数据目录 `0003`；LLM 与联网 `0004`；版本顺序 `0005`。
- **界面语言**：App、报告、文档全中文；Word 里的选项卡、按钮、宏对话框一律英文（`0006`）。
- **视觉**（2026-11-16，`0027`；11-22 改，`0028`）：设计由云端在 Visual Atelier 的 `main` 上出，本地开发先用默认界面。App 用方案 `pith`，WonderLab 的作品每种图形语言一套 `pith-wonder-<名字>`，两边不共用；用别的项目的设计系统就复制一份另起名字（如「Pith Wonder - Pomelo」），原来的不动（`CLAUDE.md` 规则 9）。
  - 简报（2026-11-17，用户填的）：
    - Pith 是用户的数字花园，沉淀通俗、真实、可视化的知识资产；
    - 多淡雅、简约、灵动，少科技感、学术、机械；
    - 参考 Maggie Appleton 的 Digital Garden；动效是亮点，界面不能呆板、静止；
    - 明暗都要。
- **花钱**（2026-11-22 改，`0028`）：所有模型、搜索、转换接口共用一个月上限（默认 $30），只看月上限，不再逐次确认、不实时算每段对话的花销；输入框下面一个小圆圈显示本月用量，点开看明细；每次调用照旧记进账本（`0018`、`0020`）。

## v0.1 Library（已验收 2026-11-10）

- 导入：Zotero 副本（条目、字段、作者、集合、标签、附件、笔记、标注、回收站，保留 Zotero key）、BibTeX / RIS / CSL JSON（`0009`）。
- **字段原则**：Zotero 的全部原始字段都存进库（`item_fields`），不丢；界面只显示常用的少数几个，其余收起。
- 搜索（FTS5，中文二元组，`0010`）、集合与标签、批量编辑、去重合并、回收站。
- PDF 阅读与标注，位置格式与 Zotero 相同（`0011`）；DOI / ISBN 联网补全，只自动填空字段（`0012`）。
- 备份、恢复、整库导出（`0013`）。数据模型见 `docs/schema.md`。
- 留到 v0.1.x、用户提出时插队：PDF 全文搜索、Zotero 增量导入、撤销系统等（`ROADMAP.md`）。

## v0.3 Fact Research（已验收 2026-11-12，`0020`、`0022`、`0023`）

- 什么问题都能问：先拆成可核实的子问题，用户确认计划后再执行。
- 检索：每个模型接口配它的专用搜索（Anthropic → Claude 网页搜索），没有的用 Tavily；也能手动加网址或文件。本机下载只取单页，失败了改用 Claude 网页抓取。
- 快照：原件 + 正文 + 网址、抓取时间、SHA-256。
- 摘录和数字由代码逐字核对，计算由代码做；核不上的不进结论。
- 可信度：不限来源、按可信度排序；中国政府官方统计默认降权（设置里可改，报告写明）。
- 结论：Opus 5.5 写 3–5 条短答，每个数字对得上已核实的事实，标出不确定的类型。
- 报告短答在前；导出 Markdown、Word、单文件 HTML；来源可一键加入文献库；同一问题可重查对比。
- 模型：计划与结论 Opus 5.5，摘证据 DeepSeek `deepseek-flash`。

## 新架构（2026-11-21 / 11-22，`decisions/0028`）

- **三个入口**：对话（做研究）、文献库（读原文、管资料）、设置（技能的长期偏好和权限）。「排版」「调查」「概念」不再是页面，变成技能。
- **技能**：一个技能一个文件夹，`SKILL.md` 写方法；模型平时只看名字和说明，对上了才读全文；用户能 `/<技能名>` 点名。App 的工具做精确操作（查文献库、核对引文、Word 选区和修订预览）。写回 Word、文献库之前先给用户看改动。
- **角色**：默认一个研究助手；工作方式明显不同的才单独做（证据审阅、写作编辑）。角色是说明，不收窄工具。
- **看得见、能纠正**：状态行、待办、问题卡、交付卡、能力菜单。
- **Agent 循环 Pith 自己写**（Rust），接多家 API；做好 Prompt Cache 前缀命中率和递归式轻量子任务。
- **组织**：研究主题只给对话分组；知识库另建，对话时勾选基于哪几个。成果由模型自动存进知识库或文献库，不绑对话。数据在知识库，元数据在文献库。
- **检索**：本机向量 + 重排模型（`src-tauri/src/local/`，Pith 只读 `~/Documents/LLM`）；回答用 API 模型。原文引用照旧逐字核对。
- **1.1.0 做**（原 v0.5）：对话 + 技能运行时 + 研究主题；事实调查、概念研究、排版改成技能；摘抄与笔记进知识库（粘贴、导入 Markdown 文件夹）；Word 润色技能。WonderLab 往后放。

**WonderLab**（1.1.0 之后，2026-11-15 定的方向仍有效）

- 程序不定死作品，只给设计模板、工具箱和必要的监控；模型按问题挑模板、自己写作品的代码，在隔离的环境里运行。
- 2D、3D 都有，必须能交互；有创造性、通俗、有趣；字多的时间轴、概念网络不做成模板。
- 忠实度能在设置里调，管作品和概念研究的解释、推演；原文引用的逐字核对、Word 引用、事实调查一直严格。
- 作品的视觉来自 Visual Atelier 的 `pith-wonder-*`，不和 App 的 `pith` 共用。
