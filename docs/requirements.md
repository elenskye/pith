# 需求（已定）

> 来源：问卷（`docs/questionnaire/round-1-answers.md`）、ASK 确认、Phase 0 验收反馈（2026-11-08）。按模块分节，只写已经拍板的；原则性内容见 `docs/brief-digest.md`。

## 总体

- 用户：一个人，研究生 / 研究者；文献以英文为主。
- 用途（未来 3 个月）：写毕业论文、日常事实调查、读书学习，以及**把 Zotero 迁移过来后卸载 Zotero**。
- 使用方式：项目驱动，忙时密集用，平时不开 → 启动要快，不常驻服务。
- 驱动项目：复现毕业论文（v0.2）、不同城市真实就业情况（v0.3，北京、天津青年就业，见下文）、《国富论》阅读（v0.4–0.5）。到对应阶段在 HANDOFF 里提醒用户提供资料。
- 形态与栈 `decisions/0001`；数据目录 `0003`；LLM 与联网 `0004`；版本顺序 `0005`。
- **界面语言**：Pith App、报告、文档全中文；Word 里的选项卡、按钮、宏对话框一律英文（`0006`）。
- 视觉：v0.1 / v0.2 简约即可；中期与 Visual Atelier 联动。时间不限，做扎实为主。

**字段原则**（用户 2026-11-08）：Zotero 的全部原始字段都存进库里（`item_fields`），保证不丢；但界面只显示少量常用字段，其余收起或不显示。Zotero 字段太多太杂是用户的痛点之一。

**数据模型**：`docs/schema.md`（0001 的 14 张表，S1–S4 用户已同意；0002 为导入补全 5 张关联表与若干可空列）。导入的映射与核对规则见 `decisions/0009`。每条文献有稳定 `uid`，能导出 CSL-JSON；中文条目的 language 按字符自动判定。

**不做**：LLM、Word 插件、网页采集、Zotero 双向同步、笔记导出、视觉打磨。PDF 全文搜索、Zotero 增量导入冲突预览、撤销系统放 v0.1.x 评估。

**验收**：真实 Zotero 库副本迁移后，用户日常使用 1 周没有丢数据、没有想回 Zotero；合成夹具自动测试 0 丢失。

## v0.2 Word Studio

### 接入（`decisions/0006`）

- Word 外直接改文件打底；**Zotero 式宏 + Word 顶栏为主**：Word 顶栏有「Pith」选项卡，点开就是全部工具。
- Office.js 代码保留，微软修复 Mac 侧载后再评估。
- Word 里的界面全英文。

### 引用

- Word 里搜索本地文献、插入 / 编辑 / 删除引文、刷新书目、切换 CSL（APA 7、Chicago、GB/T 7714）。
- 用户论文里已有的 Zotero 引文：识别并可转换为 Pith 引文（按 Zotero 条目 key 映射）。
- 学校要求：GB/T 7714-2015 顺序编码制，引文右上标；著录规则见 `local/real-thesis/cqu-requirements.md` F 节。

### 排版 Agent（`decisions/0008`）

- 模型：Claude Opus 5.5，月预算硬上限默认 $20；论文按「结构和片段」与「全文」两种方式各测一轮再定默认，规范整份发送（`decisions/0015`）。每次发送前确认（列出要发的内容与预计费用），完成后显示实际费用，设置里有本月累计（用户 2026-11-10；做法见 `decisions/0018`）。
- **必须有 Agent**。润色 Word 之前，模型先从需求文档（规范、模板、附件）中提炼精炼、完整的要求清单，每条带出处、确定度、处理方式；用户确认后生成规范与文档计划，交给确定性引擎改副本并校验。
- 文档引擎自研（`decisions/0007`）；输出前独立保真校验，不通过不交付；报告列出未处理的结构（修订、批注、文本框等）和只检查的项目。
- 「要改内容或结构」的排版功能：页眉内容（校名 / 章名、奇偶页）、页眉横线、页码分段（罗马 / 阿拉伯）、主体从奇数页开始、三线表、脚注编号格式、「二级标题紧跟一级标题时不空行」。W4 已做（`decisions/0019`）：要求清单里这些从「待做」变成「自动」，计划里要确认各部分从哪段开始、单面还是双面、哪些表格排三线表。仍做不了的（公式编号位置、四线表、表注、目录生成）列在报告里。
- W5 在 Word 里验收（`decisions/0021`）：已经另起一页的标题不再加段前分页（不多出空白页、不把一个标题拆到两页）；表格里用参考文献样式的段落按表格文字排；参考文献、编号列表自带的悬挂缩进保持不变，规范没定对齐时参考文献保持原对齐。

### 验收

用户提供的真实论文（朋友的草稿与终稿）与重庆大学规范：Agent 的提炼结果与人工样例逐条一致；排版后在 Mac Word 中目视正确，保真校验与规范核对全部通过；引文可切换并刷新。

## v0.3 Fact Research（`decisions/0020`，2026-11-12 第二轮问卷）

| # | 功能 | 备注 |
| --- | --- | --- |
| F1 | 通用事实调查 | 什么问题都能问；先拆成可核实的子问题，用户确认计划后再执行 |

**模型**：计划与结论用 Claude Opus 5.5；读网页、摘证据用便宜的执行模型（先用 DeepSeek `deepseek-flash`）。密钥三把（Anthropic、DeepSeek、Tavily），都存钥匙串。

**验收问题**：2022–2026 年北京、天津年轻人（应届生和非应届生）的就业情况，与其他一线、热门二线城市对比。指标：青年失业率、平均工资、求人倍率、灵活就业与平台就业，并主动找更客观的衡量维度。

**不做**：视觉打磨（单独排期）、单次费用上限、爬整站。

## 协作

- Agent 自主度：大胆做，可逆操作不问，每轮结束汇报；不确定的用 ASK 问。
- 汇报：用户只看 `HANDOFF.md` 摘要。
- Git：全部由用户自己做；Agent 每轮给出 git 命令模板，提交信息由用户写（2026-11-11）。提交信息全英文、极简：`v0.3.0 finished` / `v0.3.0: <xxx> improve`，不写正文与署名。
- 云端协作（v0.3 起，2026-11-11）：部分开发交给另一个账号的云端 Claude，只提交推送到 `cloud/v0.x`，编不过的 macOS 部分不改，交接写 `HANDOFF-cloud.md`，最后一律本地验收（`CLAUDE.md` 规则 7）。v0.3 里云端一口气做完它能做的部分（2026-11-12）。
- 本机测试遗留：正式运行还用得上的保留，用不上的清理（用户 2026-11-08）。
