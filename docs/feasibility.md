## 0-A Zotero 迁移

**做法**：Rust 以 `mode=ro&immutable=1` 打开 `zotero.sqlite` 副本（不加锁、不产生旁路文件）→ 无损中间模型 → 用一套独立 SQL 按 15 类（条目、字段、作者、标签、集合、集合成员、关联、附件、笔记、标注、回收站……）生成指纹比对；附件算 SHA-256 / MD5 并与 Zotero 的 `storageHash` 对照。合成夹具按真实库列名由代码生成。

**真实副本（聚合数字）**：Zotero 9.0.3 / userdata 125；普通条目 84、附件 38、笔记 27、集合 18（最深 3 层）、标注 0；15 类指纹全部一致；读取前后副本哈希不变；2 个 PDF 只在 Zotero 云端（用户确认不需要）；中文条目约 10%，都没有 language 字段；0.53 s / 8 MB。

**结论**：直接读数据库副本比 CSL JSON / RDF 导出完整（导出没有集合树、回收站、附件哈希、笔记内嵌图片关系），且不依赖 Zotero 运行。

**未验证**：其他 Zotero 版本；linked_file、标注、group 库的真实数据（用户库没有，只靠夹具）。

## 0-B Word 动态引用

**做法**：数据格式见 `decisions/0006`。引擎 citeproc-js 2.4.63 + 官方 CSL（APA 7、GB/T 7714-2015 顺序编码 / 著者-出版年、GB/T 7714-2025 顺序编码、Chicago 作者-日期）。刷新是纯函数 `planRefresh`，三种接入方式共用。`rl-docx verify` 用同一引擎从文档数据重算，逐处比对引文与书目，并核对 Zotero 域指纹。

**真实 Word（16.114）验收**：工具生成文档 → Word 导入宏、另存 .docm → 宏插入引文、切到 GB/T 顺序编码（编号按首次出现重排）→ 关闭重开、删除一处、刷新、切回 APA → Word 外刷新成 Chicago 再用 Word 打开。每步保存后确定性校验全部通过；合成 Zotero 域全程逐字不变。宏刷新约 0.2 s，Word 外刷新约 0.12 s。

**Office.js 障碍**：机构账号禁用全部加载项；个人账号下侧载清单仍被忽略（微软官方示例同样不识别，office-js #6973 回归问题）；WebKit 拦截 HTTPS 页面访问 http://localhost（bug 171934），将来要用本机受信任证书。

**宏路线的代价与对策**

| 现象 | 对策 |
| --- | --- |
| 每次打开 .docm 都弹「启用宏」 | 全局模板（.dotm）放 Word 启动文件夹，文档保持 .docx |
| 宏调用的 Node 读「文稿」触发系统权限弹窗 | 宏只连本机 Research Lab 服务 |
| Mac 版宏的对话框显示不了中文 | Word 里的界面一律英文（用户 2026-11-08 定） |
| 宏源码只能写 ASCII | 文案由服务返回 |
| 锁定的引文控件要点标题才能整块删除 | 提供「删除当前引文」命令 |

**引用样式的问题（v0.2 解决）**：APA 下中文作者只出姓；GB/T 顺序编码样式不输出引文页码；GB/T 2025 样式英文条目也用全角标点；中文条目需要按字符判定语言。

**与 Zotero 共存**：Zotero 引文域只读识别、逐字不变；域代码里有 Zotero 条目 key，可在 v0.2 映射转换。

**未验证**：Office.js 代码未在 Word 中运行；脚注里的引文；跨文档复制引文（数据部件不跟着走，目标文档刷新时报告并跳过）；数百处引文的性能。

## 0-C Word 排版保真

**做法**：排版器只改格式节点——样式表、每节纸张与页边距、与样式冲突的直接字体 / 字号 / 颜色 / 段落间距；加粗、斜体、上下标、下划线、代码字体、列表缩进、公式内部保留。样式按内置名找（中文版 Word 的样式 ID 是「1」「a」这类）；设字体时去掉主题字体属性；缺的内置样式按名新建。独立校验器（roxmltree）逐故事部件比对文字、修订删除文字、域代码、公式文字、30 类结构计数与标识；不该动的部件逐字节比对；规范核对沿样式继承链解析。11 种篡改全部能发现。

**库对比（只读入再写出，不改任何东西）**

| 库 | 结果 |
| --- | --- |
| docx-rs 0.4.22 | 读真实文档时崩溃 |
| docx-rust 0.1.11 | 丢目录域结果、公式文字、修订；正文字符 691 → 667；.docm 丢 9 个部件 |
| python-docx 1.2.0 | 内容无损，但中文字体、按字符缩进、主题字体、脚注没有 API；拒绝 .docm；按同一规范实现仍有 11 / 43 项不符 |

**合成与 Word 保存的文档**：三份全部通过（46 项规范核对）；Word 打开显示正确；排版后 0-B 引文仍可刷新。

## 真实论文测试（2026-11-08）

**材料**：用户提供的朋友毕业论文草稿（完整稿 1.0）、终稿，以及重庆大学本科毕业论文规范（2023 修订）、论文模板、参考文献著录附件。全部只放 `local/real-thesis/`，不进 Git；下面只写聚合结论。

**做法**：人工把三份规范提炼成要求清单（`local/real-thesis/cqu-requirements.md`，作为 v0.2 Agent 的对照样例），写成规范 JSON；为两份论文各写一份文档计划；用排版器处理副本。

**结果**

| 文档 | 保真校验 | 规范核对 | 段落角色映射 | 受保护区域 |
| --- | --- | --- | --- | --- |
| 终稿（约 48 页，Zotero 域 64 个、目录、4 节、2 张表、4 张图） | ✅ 文字、域、结构全部不变 | ✅ 59 项 | 正文 99 段、题注 4 段 | 封面与英文题名页 36 段外观不变 |
| 草稿（标题层级整体低一级，无封面） | ✅ | ✅ 53 项 | 标题 22 段升一级、正文 82 段、题注 4 段 | — |

不加计划直接排版终稿，封面 36 段的外观全部被改变，校验器逐段报出——证明受保护区域的核对有效。Quick Look 预览确认排版后封面与原文档一致（纸张已改为 A4）。

**真实文档才有的情况（已在排版器里处理）**

1. 正文大多不用「正文」样式：网页 / 其他软件粘贴来的 Normal (Web)、p1，靠直接格式凑出效果 → 计划里的样式映射
2. 封面、题名页靠直接格式排版，样式一改就走样 → 受保护分节 + 外观冻结 + 逐段核对
3. 题注是手动居中的普通段落，「图 3 展示了……」这类正文句子开头也像题注 → 按文字识别 + 长度上限
4. 草稿的章节用的是标题 2 / 标题 3 → 计划里的标题层级映射
5. 「关键词：」等标签的黑体是有意为之 → 保留黑体、楷体、仿宋、等宽等字体的直接设置
6. 中文字体名有中英两种写法（宋体 / SimSun）→ 核对时视为同一字体
7. 规范要求「行距固定值 20 磅」、装订线、一级标题换页、参考文献样式 → 规范新增对应字段；图片段落不用固定行距（会被裁掉）
8. 终稿纸张是 Letter（规范要求 A4）；题名 28 字（规范「一般不超过 25 字」）；图按全文编号（规范要求按章编号）→ v0.2 的「只检查」项

**未验证**：本轮 Word 窗口无法截图（屏幕休眠），排版后的终稿未在 Word 里目视检查，留给用户看（`local/real-thesis/out/final-cqu.docx`）。页眉内容、页码分段、奇数页起始、三线表、章节编号属于「要改内容或结构」的功能，v0.2 做。
