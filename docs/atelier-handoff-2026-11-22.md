## 1. 一句话和新理念

**对话是首页。知识库是文献库和对话之间的一层，放能拿来检索、引用的东西。排版、调查、概念不再是页面，变成对话里的技能。程序不限制模型，只给它更好的检索和引用工具。**

新的核心开发理念，站主 2026-11-22 的原话：

> 程序不能限制模型，特别是“每句话有出处”这样的强限制。程序做的只能是，给模型提供更好的检索工具、引用工具，帮助模型更好更严谨地输出。

落到代码里，程序只做三件事：

- **给工具**：检索知识库、读原文、引用、计算、联网。页码、段落号、原文由工具给出，模型不用背，也不用猜。
- **守站主的文件**：改 Word、改文献库条目之前，先把改动给站主看，点头才写。这一条管写文件，不管模型怎么说话。
- **守边界**：费用上限；不碰 `~/Zotero/`、`~/Pith/`；论文、网页、书里夹带的指令一律不执行。

程序不再做：给句子分类（原文、他人、解释、推演）；要求每句话有出处，或者只许依据检索到的段落回答；核对引文，核不上就删句子、打标签；用固定的步骤表规定模型先做什么、后做什么。

站主同一天提的四个问题和回应：回复限制太死 → 上面的理念；少了知识库、和文献库混在一起 → 第 2 节；首页要是对话 → 第 2 节；要大气简约，能用自然语言就用自然语言、能用 `/` 呼出就不要用按钮 → 第 3 节「界面」。

11-21 那版的四个产品决定里，**还成立的**：默认一个研究助手、角色按需切换；自动调用要看得见（一行短状态）、也能纠正；成果有自己的位置（现在是存进知识库）；SKILL 写研究方法、App 的工具做精确操作。**作废的**：三个入口（现在四个）；「技能据此分出原文、他人、解释和推演」。

## 2. 四个入口、三层数据

| 入口 | 管什么 |
| --- | --- |
| **对话**（首页） | 打开 Pith 就是对话：一句问候、一个大输入框，别的不摆。左边是对话列表（按时间，能按角色、知识库筛选，可以收起） |
| **知识库** | 一个个知识库（例：「毕业论文」「读《国富论》」）和里面的材料。一个列表、一个详情；加材料、整理都在对话里说 |
| **文献库** | 条目、元数据、附件；PDF 阅读和标注（Zotero 八色不变）；Zotero 导入、联网补全。选一段原文能直接问 Pith |
| **设置** | 七页：角色、技能、知识库与检索、模型与费用、Word 与引文、数据（数据目录、备份、导出、联网补全）、外观 |

三层数据：文献库把原料（解析出的全文、摘抄、网页）交给知识库；对话从知识库检索、读原文、引用；对话的成果再存回知识库；引用编号点开看到那一段原文，再一步回到文献库那一条。

| 层 | 管什么 | 不管什么 | 表（草拟，新表从 migration 0010 起） |
| --- | --- | --- | --- |
| 文献库 | 这是哪篇（条目、作者、元数据、集合、标签）；文件在哪（附件、阅读、标注） | 不解析全文、不建检索、不放摘抄和成果 | 照旧：`items`、`attachments`、`files`、`annotations` 等 |
| 知识库 | 能拿来检索、引用的东西：解析出的全文（带段落号、页码）、摘抄、笔记、网页快照、本机文件、扫描件，以及成果（概念卡、调查报告、WonderLab 作品、存下的好回答）。统一切成段落块，建一套索引 | 不管元数据；材料来自哪条文献只记一个指向 | `kbs`；`kb_materials`（多对多）；`materials`（种类、来自哪条文献、文件 SHA-256、解析器版本）；`passages`（序号、段落号、页码、文字）。索引在 `search.db`，只放派生数据 |
| 对话 | 角色、对话、消息、引用、后台任务、交付的成果 | 不存原文；引用只记指向哪个段落块 | `roles`、`chats`（角色、勾的知识库、预算）、`messages`、`citations`（消息、编号、段落块）、`tasks` |

- **一份材料能进多个知识库**（站主 11-22 定）：只存一份、只建一次索引。删知识库只是把材料拿出来；材料不在任何库里了，才问要不要清掉。
- **v0.4 解析好的书直接搬过来**：`concept_texts`、`concept_paragraphs` 里已有带段落号、页码的全文和中英对齐，迁成 `materials`、`passages`，不重新解析；v0.4 的卡片迁成成果，四类标签不再显示。
- **检索沿用 v0.4 修好的本机模型**：`~/Documents/LLM` 的向量和重排模型（8081、8082），Pith 只读那个文件夹；回答用 API 模型。

## 3. 对话 Agent、技能、引用、界面

**工具循环**：现在的技能是固定步骤表（`SKILL.md` 开头的 YAML `steps`），模型只能照走。新的对话 Agent 由模型看问题，自己决定查什么、读什么、要不要再查一次、什么时候问站主、最后怎么写；来回几次由模型定。

| 工具 | 给模型什么 |
| --- | --- |
| 检索知识库 | 按意思和关键词，在勾的知识库里找段落块，带出处（没勾就问全部） |
| 读原文 | 某一段的上下文、整章、对齐的另一种语言 |
| 引用 | 给段落块编号 [n]，带文献、页码、段落号。模型想引就引，程序不核对 |
| 查文献库 | 条目、作者、年份、附件 |
| 联网 | 搜索、抓网页；快照存进知识库，以后能再引 |
| 计算 | 跑算式和小段代码，数字不用口算。v0.3 的「代码核对」改成这个工具，用不用由模型定 |
| 加载技能 | 读某个技能的全文 |
| 问题卡、交付卡、待办 | 问站主（单选、多选、带推荐）；交成果；三步以上的任务在输入框上方列待办 |
| 后台任务 | 长的活（整本书的概念研究、一次事实调查）放到后台，对话里一张任务卡 |
| 存进知识库 | 把回答、卡片、报告、作品存成材料 |
| Word、改条目 | 先出修订预览，站主点头才写（唯一要点头的一类） |

**引用**（站主 11-22 定：编号引用，不核对）：回答是普通文字，引了的地方带编号 [1] [2]；不分类、不加标签、不删句子，没带编号的句子就是模型自己的话。点开编号，旁边展开那一段原文（文献、页码或段落号），再点一下回到文献库那一条。知识库里找不到，模型直接用自己的知识答（第五轮问卷 K6）。

**技能**：一个技能一个文件夹，一份 `SKILL.md`：开头是名字和一句话说明，正文用文字写研究方法（怎么读、怎么比、注意什么），可以带参考文档；不再写步骤表、`max_output_tokens`、产出种类。模型平时只看见名字和说明，任务对上了才加载全文；站主也能 `/技能名` 点名。技能可以只给某几个角色用。现有 7 个技能（问这本书、整章分析、读一段、追踪概念、反方与后世评论、假设推演、自由）改写成这种格式。

**排版、调查、概念变成技能**（站主 11-22 定：拿掉页面）：

| 现在的页 | 变成 | 留下的工具 | 拿掉的 |
| --- | --- | --- | --- |
| 调查（v0.3） | 「事实调查」`/调查` | 联网搜索、本机下载与快照、计算；报告和快照进知识库 | 固定 8 步的流水线；调查计划改成问题卡 |
| 概念（v0.4） | 「概念研究」`/概念`，另有问这本书、整章分析、读一段、追踪概念、反方、推演 | EPUB、PDF 解析成带段落号和页码的全文、中英对齐，挪到知识库「加材料」；关系图、导出照旧 | 四类句子、逐字核对、核不上删句（`concept_rejected`）；「概念」页和它的侧栏 |
| 排版（v0.2） | 「排版」`/排版`、「Word 润色」`/润色` | docx-engine 读写 Word、修订预览、应用；引文引擎；Word 里的选项卡照旧 | 「排版」页；要求清单改成问题卡。写回前给站主看，这一条留着 |
| WonderLab（v0.5） | 技能 `/画` | 设计模板、工具箱、隔离运行；作品在交付卡里打开大图、存进知识库 | 不单独做页面 |

设置跟着收：「排版 Agent」「事实调查」「概念研究」三页合进「技能」，每个技能一小页，写一段自然语言的偏好（「调查先找中文资料」）、选用哪个模型。现在的八页变成上面那七页。

**界面：四个入口，少按钮**

- 三个符号：`/` 点名技能（`/调查`、`/润色`）；`@` 请一个角色答这一回（`@审稿人 这段站得住吗`）；`#` 选这次用哪几个知识库，选了在输入框里留成一个小标签（第五轮 G2「输入框上面勾」）。
- 别的都说话：「存下来」「导出成 Word」「把这篇的标注收进毕业论文库」「以后调查先找中文资料」。
- 按钮只剩要站主拍板的地方：问题卡上的选项、Word 修订预览上的「应用」。
- 对话里看得见的：一行短状态说刚才做了什么（「找了 6 段，读了 3 段」），点开能看工具调用；成果是交付卡；后台任务是任务卡。
- 照旧的（第五轮问卷）：启动后台任务前用问题卡问一声（G4）；每段对话一个预算，超了再问（G6）；每段对话各记各的，跨对话的记忆 v0.7 加（G7）。
- **视觉和交互的细则**（站主 11-23、11-24 定）：对话历史没有按钮（⌘\ 或两指横滑，枝桠）、配色能换（纸与海、雾与赭）、状态行用 Agent 行为的动态图标、悬停「上墨」、Logo 会长、舒展和生长的动效，连同开发时要注意的，都在 `schemes/pith/DESIGN.md` 第 2、5–7 节。

## 4. 角色：学 Deva

**Deva 怎么做**（开源的本机桌面 AI Agent，Electron，MIT 许可，对话是唯一入口；用得上的写全在这里，不用再去看它的仓库）：

- 角色设定是一份文件（`personas/<id>.md`）：身份、性格、语气、行文风格。系统规范（工具、执行边界、澄清和计划的规矩）和角色设定分开，所以换角色不削弱能力。
- 一个对话绑一个角色，建对话时选；没选或角色删了，回到默认角色。默认角色不能删。
- 角色不收窄内置工具；技能和 MCP 可以只给某些角色用，形成角色专属的能力。子智能体不带角色设定，免得风格影响检索和调研的结论。
- 角色名片：头像、名称、专长、偏好模型，加一段设定。角色的资料页分「对话」「能力」「记忆」三栏，有「开始对话」。
- 建角色可以填表，也可以在对话里说，模型拟一张「确认角色名片」，用户接受或拒绝。
- 输入框里 `@` 一个已有角色请它协助，不改变主角色的做法；主角色还能临时加「成员」分头干活（多成员协作）。
- 对话里看得见的：三步以上的任务在输入框上方列待办；要用户定的事用问题卡问；计划可以批准、要求改、忽略；成品以交付卡交出来。Deva 没有授权弹框，模型直接读写文件、执行命令。

**Pith 取什么**：一个对话绑一个角色（默认 Pith）；`@` 请别的角色答一回，对话还是原来的角色；角色是一份说明（身份、语气、做事方式），加默认知识库、偏好模型、常用技能；角色不收窄工具（和第 1 节的理念一致）；在对话里说「帮我建一个专看统计方法的角色」，Pith 拟一张角色名片让站主接受、改或拒绝。**不取**：没有授权弹框（Pith 写回 Word、文献库前一定先给站主看）；多成员协作这一版不做，v0.7 以后再看；手机上的 IM 机器人不做。只有做事方式明显不同的才单独做成角色（站主 11-21）。

| 角色 | 做什么 | 默认知识库 | 常用技能 |
| --- | --- | --- | --- |
| **Pith**（研究助手，默认） | 什么都能问。先给结论，再给依据和编号；该用哪个技能自己挑 | 上一次勾的 | 全部 |
